>
> **具体适配要求**：
> - 所有涉及 LLM 调用的功能，必须通过 `LLMAdapter` 统一接口，支持手动/API 双模式
> - 所有涉及后端计算的业务逻辑，迁移到前端 `src/features/{模块名}/services/` 目录
> - 所有数据操作通过 Supabase Client SDK，不直接写 SQL
> - Neo4j 图查询通过 Supabase Edge Functions 代理，前端调用 Edge Function URL
> - 向量搜索使用 Supabase pgvector，替代原 Milvus
> - 缓存操作使用前端内存缓存 + Zustand persist，替代原 Redis
> - **四层上下文架构**（冷/温/热/动态压缩）全部在前端 `src/shared/context/` 中实现

> - **ContextRouter** 在手动模式下通过 LLMAdapter 弹窗调用 LLM 决定上下文注入，在 API 模式下通过 Edge Function 调用
> - 冷存储数据通过 Supabase 按需查询（不预加载），温存储摘要缓存在 Zustand persist 中

> **所属模块：** 核心基础设施

> **状态：** ✅ 已设计
> **版本：** v1.0
> **最后更新：** 2026-04-21

## 1. 功能概述

本功能定义了 AI 辅助长篇小说创作平台的上下文管理系统。长篇小说创作涉及海量设定信息（世界观、角色、伏笔、历史情节等），远超 LLM 的上下文窗口限制。本系统通过四层上下文架构（冷存储、温存储、热存储、动态压缩）实现信息的分层管理，确保在有限的 token 预算内，为 Agent 提供最相关、最高质量的信息。

系统核心组件包括：

1. **四层上下文架构（C-01）：** 将信息按访问频率和相关性分为冷、温、热三层，加上动态压缩层，实现智能的信息分级管理。
2. **ContextBudgetManager（C-02）：** 根据模型自动调整 token 预算，支持手动覆盖，确保上下文不超限。
3. **ContextRouter（C-03）：** 由 LLM 决定每次请求需要注入哪些上下文内容，实现精准检索。
4. **实时检索生成范式（C-04）：** 最小启动 → 生成 → 遇到细节暂停 → 精确查询 → 继续生成，实现按需加载。

此外，系统还包含模块集成（角色上下文、节奏上下文、伏笔上下文）、运行时增强（上下文污染防护、循环检测、上下文隔离）等能力。

## 4. 业务规则

### 4.1 四层架构规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-01 | 冷存储信息不得直接进入 LLM 上下文窗口，必须通过检索后以摘要或片段形式注入。 |
| BR-02 | 温存储的摘要索引总量不超过 4100 tokens，超出时按 LRU（最近最少使用）策略淘汰。 |
| BR-03 | 热存储的 token 范围为 3K-10K，具体值由 ContextBudgetManager 根据当前预算动态调整。 |
| BR-04 | 动态压缩触发条件：上下文使用率达到预算的 85% 时启动压缩，优先压缩低介入度内容。 |
| BR-05 | 冷 → 温的升级由 LLM 全权管理（决策 #18），包括升级时机和压缩策略。 |
| BR-06 | 温 → 热的升级由 ContextRouter 根据当前任务相关性决定。 |
| BR-07 | 热 → 温的降级在任务完成后自动触发，释放热存储空间。 |

### 4.2 预算管理规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-08 | ContextBudgetManager 根据模型自动计算预算（决策 #18），公式为：可用预算 = 模型上下文窗口 - 系统提示占用 - 历史消息占用 - 生成预留（默认 1000 tokens）。 |
| BR-09 | 作者可手动覆盖自动预算，但不得低于最低安全阈值（模型上下文窗口的 20%）。 |
| BR-10 | 角色上下文不设硬限制（决策 #21），由 ContextBudgetManager 根据当前预算动态管控。 |
| BR-11 | 预算分配优先级：系统提示 > 热存储 > 生成预留 > 温存储摘要。 |

### 4.3 上下文路由规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-12 | ContextRouter 的路由决策由 LLM 生成，不得使用硬编码规则。 |
| BR-13 | 路由决策结果缓存有效期为同一任务会话内，任务切换后缓存失效。 |
| BR-14 | 当 ContextRouter 无法确定注入内容时，默认注入温存储摘要和当前任务相关的热存储。 |

### 4.4 实时检索生成规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-15 | 最小启动时，仅注入系统提示 + 核心设定摘要（< 500 tokens）。 |
| BR-16 | 细节暂停的触发条件：生成过程中遇到需要具体设定细节的标记（如角色名、地名、历史事件引用）。 |
| BR-17 | 精确查询的结果注入后，如果上下文超过预算，必须先压缩再继续生成。 |
| BR-18 | 单次生成过程中的最大暂停次数为 3 次，超过后强制使用已有信息继续生成。 |

### 4.5 上下文污染防护规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-19 | 信号质量评估的评分维度：信息准确性、信息时效性、信息完整度、与任务相关度。 |
| BR-20 | 质量评分低于 60 分的信息被过滤，60-80 分的信息被降级到温存储，80 分以上的信息正常注入。 |
| BR-21 | 介入度分为三级：高（直接相关）、中（间接相关）、低（背景参考）。高介入度信息优先注入，低介入度信息在预算紧张时优先压缩。 |

### 4.6 上下文隔离规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-22 | 每个 Agent 的上下文注入由 ContextRouter 根据 Agent 类型独立决策。 |
| BR-23 | Agent 间的数据传递格式为结构化 JSON，包含：摘要内容、置信度、来源引用。 |
| BR-24 | Agent 的独立 token 预算由 ContextBudgetManager 在总预算中按比例分配，默认比例为均分。 |

## 5. 验收标准（AC）

### AC-01: 四层上下文架构

**前置条件：** 项目已有世界观设定、角色信息和历史章节。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 查看冷存储内容 | 所有设定信息存储在数据库中，不直接出现在 LLM 上下文中。 |
| 2 | 查看温存储摘要 | 温存储包含设定摘要索引，总 token 数 <= 4100。 |
| 3 | 触发写作任务 | 热存储自动加载当前任务相关内容，token 数在 3K-10K 范围内。 |
| 4 | 模拟上下文接近预算上限（85%） | 动态压缩自动触发，低介入度内容被压缩，上下文总量回落到安全范围。 |

### AC-02: ContextBudgetManager 自动预算

**前置条件：** 系统已配置目标模型（如 GPT-4，上下文窗口 128K）。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 查看自动计算的预算 | 可用预算 = 128K - 系统提示 - 历史消息 - 生成预留，数值正确。 |
| 2 | 手动覆盖预算为 50K | 预算更新为 50K，系统提示和生成预留不变，热存储和温存储空间相应调整。 |
| 3 | 尝试设置预算低于最低安全阈值（128K * 20% = 25.6K） | 系统拒绝并提示最低安全阈值。 |
| 4 | 切换模型为 GPT-4o（上下文窗口 32K） | 预算自动重新计算，适配新模型的上下文窗口。 |

### AC-03: ContextRouter 智能路由

**前置条件：** 项目有丰富的设定信息。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 触发写作任务"写主角进入魔法森林的场景" | ContextRouter 选择注入：主角信息、魔法森林设定、相关伏笔，不注入无关角色和地点。 |
| 2 | 触发审查任务"检查第三章逻辑" | ContextRouter 选择注入：审查规则、第三章内容、相关前文摘要，不注入风格设定。 |
| 3 | 连续触发相同任务 | 第二次路由决策命中缓存，不调用 LLM，响应时间 < 100ms。 |

### AC-04: 实时检索生成范式

**前置条件：** 项目有详细的世界观设定（存于冷存储）。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 触发写作任务 | 最小启动，仅注入核心摘要（< 500 tokens），开始生成。 |
| 2 | 生成过程中遇到角色名引用 | 系统暂停生成，从冷存储检索该角色的详细信息。 |
| 3 | 检索结果注入后 | 继续生成，内容中角色描写与设定一致。 |
| 4 | 暂停次数达到 3 次 | 第 4 次需要细节时不再暂停，使用已有信息继续生成。 |

### AC-05: 上下文污染防护

**前置条件：** 上下文中有高质量和低质量信息混合。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 注入一条质量评分 50 的信息 | 该信息被过滤，不进入上下文。 |
| 2 | 注入一条质量评分 70 的信息 | 该信息被降级到温存储，不直接进入热存储。 |
| 3 | 注入一条高介入度（直接相关）但质量评分 75 的信息 | 由于介入度高，信息仍被注入热存储（介入度联动）。 |
| 4 | 预算紧张时（> 85%） | 低介入度信息优先被压缩，高介入度信息保留。 |

### AC-06: 循环检测与中断（上下文层面）

**前置条件：** 两个 Agent 之间存在循环交互。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 模拟 Agent A 和 Agent B 连续 3 轮交互无进展 | 循环检测触发，自动中断交互。 |
| 2 | 查看中断日志 | 日志记录循环检测详情：涉及 Agent、轮次、相似度分数。 |
| 3 | 相同参数的工具调用 | 第二次调用直接返回缓存结果，token 消耗不增加。 |

### AC-07: 子 Agent 上下文隔离

**前置条件：** WriterAgent 和 ReviewerAgent 同时运行。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 检查 WriterAgent 注入内容 | 包含写作相关上下文（大纲、角色、伏笔），不包含审查规则。 |
| 2 | 检查 ReviewerAgent 注入内容 | 包含审查相关上下文（审查标准、历史结果），不包含完整写作草稿。 |
| 3 | Agent A 向 Agent B 传递信息 | 信息以结构化 JSON 摘要形式传递，不包含原始上下文。 |
| 4 | 检查各 Agent token 使用 | 各 Agent token 消耗独立统计，总和不超过总预算。 |

### AC-08: 模块集成 - 角色上下文注入

**前置条件：** 场景涉及 3 个角色，项目有 10 个角色。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 触发写作任务 | ContextRouter 自动识别场景相关角色（3 个），仅注入这 3 个角色的运行时信息。 |
| 2 | 查看注入的角色信息 | 包含：角色当前状态、角色关系、近期行为摘要。 |
| 3 | 角色信息总量检查 | 角色上下文 token 数在预算分配范围内。 |

### AC-09: 模块集成 - 节奏上下文注入

**前置条件：** RhythmProfiler 已生成节奏画像。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 触发写作任务 | 节奏上下文按优先级 3 注入，包含当前节奏画像。 |
| 2 | 查看注入内容 | 包含：节奏画像、近期偏差历史、调整建议。 |
| 3 | 预算紧张时 | 节奏上下文（优先级 3）在角色上下文（优先级 2）之后被压缩。 |

### AC-10: 模块集成 - 伏笔上下文注入

**前置条件：** 项目有 5 条待回收伏笔。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 触发写作任务 | 伏笔上下文按优先级 5 注入，包含与当前场景相关的待回收伏笔。 |
| 2 | 查看注入内容 | 包含：待回收伏笔列表（按紧急程度排序）、已埋伏笔摘要。 |
| 3 | 预算紧张时 | 伏笔上下文（优先级 5）最先被压缩。 |
