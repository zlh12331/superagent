# B7 伏笔协调层

> **所属模块：** B7 伏笔协调层（独立模块，数据协调层）
> **需求来源：** AI/Agent 网文写作软件 PRD v5.2 + 需求澄清记录（#10）
> **状态：** 已设计，待技术方案
> **版本：** v1.0
> **最后更新：** 2026-04-21

## 1. 功能概述

B7 伏笔协调层是 AI 辅助长篇小说创作平台的独立数据协调模块，负责全局伏笔的统一管理、自动识别、回收检测和密度监控。模块定位为"数据协调层"，不直接面向用户，而是为 WriterAgent、ReviewerAgent、OutlineAgent 等 Agent 提供伏笔数据服务和检查能力。

模块核心能力包括：

1. **统一伏笔视图（B7-01）：** 通过 `get_unified_view()` 接口提供全局伏笔的合并视图，整合手动标记和 AI 自动识别的伏笔数据。
2. **伏笔分类体系（B7-02）：** 五种伏笔类型（道具/人物/情节/世界观/误导；数据库存储值：prop/character/plot/worldview/misdirection），每种类型有不同的管理策略和回收检测逻辑。
3. **AI 伏笔识别引擎（B7-03）：** 写作完成后自动扫描识别潜在伏笔信号（悬而未决/异常强调/角色异常反应/重复出现），降低作者手动标记的负担。
4. **回收自动检测器（B7-04）：** 两步检测机制——算法层关键词匹配 + LLM 层语义判断，含 30 秒超时和降级策略，确保回收检测的准确性和实时性。
5. **伏笔密度监控（B7-05）：** 监控活跃伏笔数量上限、近 10 章趋势、未兑现比率和密度评估，防止伏笔过度堆积或遗忘。
6. **伏笔依赖链（B7-06）：** 支持 `depends_on` / `triggers` 关系，含循环依赖检测，确保伏笔间的逻辑一致性。
7. **误导伏笔特殊处理（B7-07）：** 误导伏笔不触发回收提醒，"回收"=揭示真相，与普通伏笔区分管理。
8. **伏笔仪表盘 API（B7-08）：** 提供 8 个公开方法，供 Orchestrator 和其他 Agent 调用伏笔数据。

此外，模块还包含统一状态机（B7-09）、事件驱动转换（B7-10）和读者记忆衰减（B7-11）三大状态管理能力。

### 核心设计原则

- **独立模块定位**：B7 作为独立数据协调层运行，不嵌入任何 Agent 内部，通过 API 和事件总线提供服务
- **AI 辅助不替代**：AI 自动识别的伏笔为"建议"状态，需作者确认后才进入正式管理
- **事件驱动**：伏笔状态转换由剧情事件触发，而非简单的章数倒计时
- **密度可控**：活跃伏笔数量有上限预警，防止伏笔过度堆积影响叙事质量
- **复用已有模型**：读者记忆衰减复用 B3 衰减模型，避免重复建设

| 编号 | 需求 | 说明 | 状态 | 优先级 |

| B7-09 | 统一状态机 | 伏笔生命周期状态机，包含八个状态：（注：状态机使用大写逻辑名，数据库存储为小写值，如 PLANNED → 'planned'）(1) `SUGGESTED`：AI 识别产出，作者确认前（仅 AI 自动识别的伏笔经过此状态）；(2) `PLANNED`：已规划（来自大纲或手动标记，尚未在正文中出现）；(3) `ACTIVE`：已激活（已在正文中埋设，等待回收）；(4) `DORMANT`：休眠（长时间未提及，读者记忆值低）；(5) `RESOLVED`：已回收（伏笔被兑现）；(6) `ABANDONED`：已废弃（作者决定不再回收）；(7) `REVEALED`：误导伏笔揭示真相（仅误导伏笔使用）；(8) `IGNORED`：作者拒绝 AI 建议（从 SUGGESTED 转入的终态）。状态转换需满足前置条件，非法转换被拒绝。SUGGESTED 相关转换：SUGGESTED → PLANNED（作者确认）、SUGGESTED → IGNORED（作者拒绝）。IGNORED 为终态，不可再转换。 | ✅ 已设计 | P0 |

| B7-11 | 读者记忆衰减 | 复用 B3 因果链检测的读者记忆衰减模型。伏笔的读者记忆值计算：(1) 初始值 1.0（伏笔刚被埋设）；(2) 每章衰减 `memory *= 0.98`；(3) 间接提及 `memory += 0.1`；(4) 直接提及重置为 1.0。记忆值 < 0.3 时触发预警"读者可能已遗忘此伏笔"，建议作者在近期回收或重新提及。衰减数据同步到 B7-01 统一视图和 B7-05 密度监控。 | ✅ 已设计 | P1 |

## 4. 业务规则

### 4.1 伏笔分类规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-01 | 每条伏笔必须归属五种类型之一：道具（prop）、人物（character）、情节（plot）、世界观（worldview）、误导（misdirection） |
| BR-B7-02 | 伏笔类型在创建时指定，后续可由作者修改，但修改需记录变更历史 |
| BR-B7-03 | 不同类型的伏笔在密度监控中权重不同：情节伏笔 x1.5、人物伏笔 x1.2、世界观伏笔 x1.2、道具伏笔 x1.0、误导伏笔 x0.8（建议值，待技术设计阶段确认） |
| BR-B7-04 | 误导伏笔不纳入"未兑现比率"的计算（避免误导伏笔拉高比率） |

### 4.2 伏笔识别规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-05 | AI 自动识别的伏笔初始状态为"建议"（SUGGESTED），不进入正式管理流程 |
| BR-B7-06 | 作者确认后，"建议"伏笔转为 PLANNED 状态，进入正式管理 |
| BR-B7-07 | 作者拒绝后，"建议"伏笔标记为"已忽略"，保留记录但不参与管理 |
| BR-B7-08 | 同一段内容被多次识别为伏笔建议时，仅保留置信度最高的一条 |

### 4.3 回收检测规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-09 | 回收检测在每章完成后自动触发（通过 `CHAPTER_COMPLETED` 事件） |
| BR-B7-10 | 算法层检测在 500ms 内完成，筛选出潜在回收信号 |
| BR-B7-11 | LLM 层检测超时 30 秒则降级为仅算法层结果，标记为"待确认" |
| BR-B7-12 | 降级后的"待确认"结果在下次检查时优先重新评估 |
| BR-B7-13 | 回收确认需要作者操作（自动检测为"建议回收"，作者确认后转为 RESOLVED） |
| BR-B7-14 | 误导伏笔不触发常规回收检测，仅检测"揭示真相"信号 |

### 4.4 密度监控规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-15 | 活跃伏笔数上限默认 30 条（初始建议值），可通过配置调整 |
| BR-B7-16 | 活跃伏笔数达到上限 80%（24 条）时，提示"伏笔数量接近上限" |
| BR-B7-17 | 活跃伏笔数达到上限 100%（30 条）时，预警"伏笔堆积风险，建议先回收部分伏笔" |
| BR-B7-18 | 未兑现比率 = 未回收伏笔数 / (总伏笔数 - 废弃伏笔数 - 误导伏笔数) |
| BR-B7-19 | 未兑现比率 > 60% 时预警"伏笔回收率偏低" |
| BR-B7-20 | 密度评分 < 40 分时预警"伏笔管理健康度不足" |

### 4.5 依赖链规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-21 | 添加 `depends_on` 关系时，自动进行循环依赖检测 |
| BR-B7-22 | 检测到循环依赖时拒绝添加，并提示作者具体的环路径 |
| BR-B7-23 | 被依赖的伏笔未回收时，依赖它的伏笔暂停回收检测（不触发 B7-04） |
| BR-B7-24 | `triggers` 关系的目标伏笔在源伏笔回收后自动从 PLANNED 转为 ACTIVE |

### 4.6 状态机规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-B7-25 | PLANNED → ACTIVE：伏笔在正文中首次出现时自动转换 |
| BR-B7-26 | ACTIVE → DORMANT：读者记忆值 < 0.3 且连续 15 章未被直接提及 |
| BR-B7-27 | DORMANT → ACTIVE：伏笔被直接或间接提及，读者记忆值回升至 >= 0.3 |
| BR-B7-28 | ACTIVE/DORMANT → RESOLVED：回收检测通过且作者确认 |
| BR-B7-29 | 任意状态 → ABANDONED：作者手动废弃 |
| BR-B7-30 | 误导伏笔 ACTIVE/DORMANT → REVEALED：揭示真相且作者确认 |
| BR-B7-31 | RESOLVED/ABANDONED/REVEALED 为终态，不可再转换 |

### 4.7 读者记忆衰减规则

## 附录 B：术语表

| 术语 | 定义 |
|------|------|
| 伏笔 | 在故事前期埋下的、预期在后期回收的叙事元素 |
| 伏笔埋设 | 在正文中引入伏笔元素的过程 |
| 伏笔回收 | 在后续情节中兑现或回应前期伏笔的过程 |
| 误导伏笔 | 故意引导读者产生错误预期的伏笔，"回收"=揭示真相 |

| 读者记忆衰减 | 模拟读者对伏笔的记忆强度随章节递减的数学模型（复用 B3） |
| 伏笔密度 | 衡量当前活跃伏笔数量和回收健康度的综合指标 |
| 依赖链 | 伏笔间的逻辑依赖关系（depends_on / triggers），以 DAG 存储 |
| 状态机 | 伏笔生命周期管理：PLANNED → ACTIVE → DORMANT → RESOLVED / ABANDONED |
| 事件驱动转换 | 伏笔状态转换由剧情事件触发，而非章数倒计时 |
| 回收检测器 | 两步检测机制（算法层 + LLM 层），自动检测伏笔是否已被回收 |
| 降级策略 | LLM 层超时 30 秒后降级为仅算法层结果，标记为"待确认" |

              │ 未提及     ▼           │
