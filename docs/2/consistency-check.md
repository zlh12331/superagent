# 第一部分：B2 隐含信息不一致检测

## 1. 功能概述

B2 隐含信息不一致检测是 ReviewerAgent 的核心检查引擎，负责在写作全过程中检测作品内部的逻辑矛盾和设定冲突。模块采用"渐进式四层检查"策略，从实时毫秒级硬规则拦截到发布前全量扫描，覆盖世界观规则、角色能力、身体状态、场景连续性、叙事视角、对话匹配、因果关系等 17 种检查机制。

B2 作为独立模块提供检查引擎能力，由 ReviewerAgent 统一调度执行。检查结果通过严重性分级（critical/high/medium/low/info）和读者影响加权（主角 x3.0 / 主要角色 x2.0 / 重要配角 x1.0 / 龙套 x0.3）进行优先级排序，配合作者回答流程（A/B/C/D）和误报反馈学习机制，确保检查精准且不干扰创作心流。

### 核心设计原则

- **LLM 优先，算法补位**：语义类检查由 ReviewerAgent 通过 LLM 执行，纯规则类检查作为工具函数
- **渐进式检查**：实时 4 条（B2-01/02/04/05，铁事实+硬规则）→ 段落间 5 条（B2-03/06/07/08/09，能力+状态+视角）→ 章节完成 8 条（B2-10~17）→ 发布前（全量）
- **宁严勿松**：硬规则零容忍，软规则允许作者覆盖
- **介入度控制**：检查频率和展示方式由 AI 介入度滑块控制，替代固定冷却期

## 4. 业务规则

### 4.1 检查执行规则

- **BR-B2-01**：第一层实时检查（B2-01/02/04/05）必须在用户输入后 100ms 内完成
- **BR-B2-02**：第二层段落间检查（B2-03/06/07/08/09）在段落完成后 3 秒内完成
- **BR-B2-03**：第三层章节完成检查（B2-10~17）在章节保存后 30 秒内完成
- **BR-B2-04**：第四层发布前检查为全量检查，时间不限但需显示进度

### 4.2 严重性分级规则

- **BR-B2-05**：critical 级别（硬约束违反）→ 行内红色标记，无冷却，强制处理
- **BR-B2-06**：high 级别（高概率问题）→ 侧边栏黄色标记，冷却策略由介入度控制系统统一管理（参见 PRD §7.3 介入度控制）
- **BR-B2-07**：medium 级别（可能问题）→ 后台记录，无主动通知
- **BR-B2-08**：low 级别（参考）→ 后台记录，无主动通知
- **BR-B2-09**：info 级别（信息提示）→ 后台记录，无主动通知

### 4.3 作者回答流程规则

- **BR-B2-10**：选择 A（确认矛盾）→ 系统记录为已确认，不影响后续检查
- **BR-B2-11**：选择 B（补充设定）→ 系统创建新设定条目，自动更新相关检查规则
- **BR-B2-12**：选择 C（故意设计）→ 系统标记为"有意为之"，后续不再检查同类问题
- **BR-B2-13**：选择 D（需要帮助）→ 系统调用 ReviewerAgent 提供修改建议

### 4.4 误报反馈规则

- **BR-B2-14**：同类误报累计 ≥ 5 次后，自动降低该类检查灵敏度 20%
- **BR-B2-15**：同类误报累计 ≥ 10 次后，加入白名单，不再检查
- **BR-B2-16**：误报分类维度：检查类型 + 实体类型 + 叙事阶段 + 文本类型

### 4.5 叙事阶段感知规则

- **BR-B2-17**：铺垫期（pacing=slow/medium）→ 降低性格/能力检查灵敏度 30%
- **BR-B2-18**：高潮期（pacing=climax）→ 降低性格检查灵敏度 50%
- **BR-B2-19**：日常期（pacing=medium）→ 所有检查正常灵敏度
- **BR-B2-20**：叙事阶段由当前章纲的 pacing 字段推断

### 4.6 读者影响加权规则

- **BR-B2-21**：检查结果的基础严重性 x 角色重要性权重 = 最终展示优先级
- **BR-B2-22**：角色重要性分级：主角（protagonist, x3.0）、主要角色（major, x2.0）、重要配角（supporting, x1.0）、龙套（minor, x0.3）
- **BR-B2-23**：加权仅影响展示排序，不影响检查逻辑本身

### 4.7 文本类型差异化规则

- **BR-B2-24**：梦境/闪回/比喻/假设中的逻辑矛盾不标记为 critical
- **BR-B2-25**：谎言/角色认知偏差中的事实错误降低一级严重性
- **BR-B2-26**：内心独白中的世界观违反仍标记为 critical（角色内心不应违反世界观）

# 第二部分：B3 因果链断裂检测

> **注意**：B3 与 B2 在同一文档中，但为独立模块。B3 的数据管理独立运行，检查逻辑由 ReviewerAgent 调用。

---

## 1. 功能概述

B3 因果链断裂检测模块负责追踪作品中所有引入元素（角色、物品、设定、伏笔、势力等）的生命周期，确保因果链完整、读者记忆连贯。模块采用"元素三态管理"（active → dormant → dead）和"读者记忆衰减模型"，通过分层检查策略（每章必跑 → 每 10 章 → 大纲变更时 → 发布前）实现精准的因果链断裂检测。

B3 的数据管理独立于 ReviewerAgent，作为独立模块提供元素状态追踪、重要性推断、共振推荐等服务。检查逻辑由 ReviewerAgent 调用执行。

### 核心设计原则

- **宁可漏报不误报**：误报会杀死功能，漏报可接受
- **重要性由作者行为决定**：不靠猜测，观察后续行为（提及次数、间隔、篇幅）
- **主动推荐优于被动预警**：通过场景-元素共振推荐帮作者自然维护元素
- **数据管理独立**：元素状态数据独立管理，不依赖 ReviewerAgent

## 4. 业务规则

### 4.1 元素三态管理规则

- **BR-B3-01**：元素首次引入时默认为 active 状态，初始记忆值 1.0
- **BR-B3-02**：active → dormant 转换条件：连续 20 章未被直接提及（间接提及不计入）
- **BR-B3-03**：dormant → dead 转换条件：连续 40 章未被任何形式提及（含间接提及）
- **BR-B3-04**：dead 状态元素不再参与常规检查，但保留历史记录
- **BR-B3-05**：任何状态被直接提及后，记忆值重置为 1.0，状态回到 active
- **BR-B3-06**：状态转换阈值可通过 PluginConfigLayer 按题材配置

### 4.2 读者记忆衰减规则

- **BR-B3-07**：记忆值初始值 1.0（刚引入或直接提及后）
- **BR-B3-08**：每章衰减公式：`memory = memory * 0.98`
- **BR-B3-09**：间接提及（影子）增益：`memory = memory + 0.1`（不超过 1.0）
- **BR-B3-10**：预警阈值：`memory < 0.3` 时触发"读者可能已遗忘"预警
- **BR-B3-11**：记忆值计算为纯算法，不依赖 LLM

### 4.3 重要性推断规则

- **BR-B3-12**：重要性评分 = 提及次数权重(0.4) + 提及间隔权重(0.3) + 篇幅权重(0.3)
- **BR-B3-13**：提及次数：统计元素在最近 50 章中的直接提及次数
- **BR-B3-14**：提及间隔：最近一次提及距今的章数，间隔越短分数越高
- **BR-B3-15**：篇幅：元素在最近一次提及时的上下文篇幅（字符数），篇幅越长分数越高
- **BR-B3-16**：重要性评分由算法计算基础值，LLM 可辅助调整（介入度 ≥ 60% 时）

### 4.4 分层检查规则

- **BR-B3-17**：第一层（每章必跑）：更新所有 active 元素的记忆值，检查是否触发 dormant 转换。毫秒级完成
- **BR-B3-18**：第二层（每 10 章）：扫描所有 dormant 元素，检查是否有"影子"存在，评估是否需要预警。秒级完成
- **BR-B3-19**：第三层（大纲变更时）：重评估受大纲变更影响的元素状态和重要性。秒级完成
- **BR-B3-20**：第四层（发布前）：全量因果链检查，包含所有状态的元素。分钟级完成

### 4.5 伏笔回收质量评估规则

- **BR-B3-21**：时机适当性（权重 0.30）：读者记忆值在 0.3-0.7 之间为最佳时机
- **BR-B3-22**：回收方式（权重 0.25）：自然回收（通过剧情发展）> 主动回收（专门章节说明）
- **BR-B3-23**：完整性（权重 0.25）：伏笔线索被回应的比例
- **BR-B3-24**：情感冲击（权重 0.20）：回收时读者的情感反应强度
- **BR-B3-25**：综合评分 = 各维度得分 x 权重之和，满分 1.0

## 附录 B：术语表

| 术语 | 定义 |

| 严重性分级 | critical / high / medium / low / info 五级问题严重性分类 |

| 读者记忆衰减 | 模拟读者对元素的记忆强度随章节递减的数学模型 |
