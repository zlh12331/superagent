## 1. 功能概述

本功能定义了 AI/Agent 网文写作软件的知识库系统与搜索引擎层。知识库是整个创作平台的数据底座，为所有 Agent（WriterAgent、ReviewerAgent、CharacterAgent 等）提供结构化的设定、角色、作品知识服务。搜索引擎层采用"四引擎并行"架构，覆盖全文关键词搜索、语义向量搜索、实体精确查找和关系图查询四大场景，确保在海量设定信息中快速、精准地检索所需内容。

功能分为三个核心部分：

1. **搜索层（四引擎并行，决策 #32~#33）：** 通过 PostgreSQL tsvector/tsquery 实现全文关键词搜索（zhparser 中文分词），pgvector 实现语义向量搜索，EntityIndex 实现实体 O(1) 精确查找，Neo4j 实现关系图查询。四引擎并行检索，结果按相关性加权合并，为 Agent 和用户提供统一的搜索接口。

2. **知识库增强（决策 #48~#50）：** 包含外部知识导入（支持 txt/md/pdf 参考资料自动索引）、知识版本快照（按卷自动生成，支持历史设定查询）和知识完备度评估（X-12 九维健康度新增 knowledge_health 维度）三大增强能力。

3. **知识库基础结构：** 包含 EntityIndex（实体倒排索引）、世界观知识库（力量体系、地理、阵营）、角色知识库（CharacterAgent 五层记忆）、作品知识库（章节摘要、事件索引）四大基础模块。

### 核心设计原则

- **四引擎并行，结果融合**：全文、向量、实体、图查询并行执行，按场景自动选择最优引擎或融合多引擎结果
- **知识分层隔离**：严格区分"作品事实"（作品内已确立的设定）和"参考资料"（外部导入的参考内容），检索优先级：作品知识 > 绑定参考 > 全局参考
- **版本可追溯**：长篇连载中设定会随剧情演化，知识版本快照确保可查询任意章节时间点的设定状态
- **LLM 优先，算法补位**：语义理解、知识提取由 LLM 执行，索引构建、全文搜索、实体查找由算法层完成
- **知识完备度可量化**：通过九维健康度评分中的 knowledge_health 维度，量化评估作品知识库的完整性和健康度

| KS-22 | 快照与一致性检查联动 | B2 一致性检查使用章节时间点的快照数据校验，而非最新版知识库。逻辑：(1) 检查第 N 章内容时，加载第 N-1 章时间点的快照作为"事实基准"；(2) 对比第 N 章新内容与快照中的设定是否矛盾；(3) 避免因设定演化（如角色能力提升）而产生误报（如"第 50 章角色会飞，但第 10 章不会"不是矛盾）。 | Draft | P1 |
| KS-23 | 快照差异对比 | 支持两个快照之间的差异对比：(1) 选择两个卷的快照；(2) 系统生成差异报告，列出所有变更的设定项（新增/修改/删除）；(3) 差异按类别分组（世界观/角色/伏笔/实体）。帮助作者追踪设定演化轨迹。 | Draft | P2 |
| KS-24 | 手动快照创建 | 除自动快照外，作者可手动创建知识库快照：(1) 在任意章节位置手动创建快照（用于标记重要设定节点）；(2) 为手动快照添加备注说明；(3) 手动快照与自动快照使用相同的存储和查询机制。 | Draft | P2 |

#### 3.2.3 知识完备度评估（决策 #50，KS-25 ~ KS-28）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| KS-25 | knowledge_health 维度 | X-12 作品健康度评分从八维扩展到九维，新增 `knowledge_health`（知识完备度）维度。评分范围 0-100，由以下子指标加权计算（权重为建议值，待技术设计阶段确认）：(1) B3 元素活跃度（权重 20%）——核心角色和设定在近 N 章的出现频率；(2) B7 伏笔密度（权重 20%）——活跃伏笔数量和密度的健康度；(3) 世界观设定覆盖率（权重 30%）——已定义设定占必要设定的比例（力量体系、地理、阵营等）；(4) 角色关系网密度（权重 30%）——已建立关系数占可能关系数的比例。 | Draft | P1 |
| KS-26 | 健康度报告生成 | 每卷完成时自动生成知识库健康度报告，内容包括：(1) knowledge_health 总分及各子指标得分；(2) 与上一卷的对比（趋势箭头：上升/持平/下降）；(3) 各子指标的详细分析（哪些角色不活跃、哪些设定未覆盖、伏笔密度是否健康、关系网是否有孤立节点）；(4) 改进建议（如"角色 X 已 20 章未出场，建议安排互动"）。 | Draft | P1 |
| KS-27 | 设定覆盖率评估 | 评估世界观设定的覆盖完备度。必要设定类别（由 WorldBuilderAgent 定义）包括：(1) 力量体系——等级划分、晋升条件、能力范围；(2) 地理设定——主要地点、地理关系、距离；(3) 阵营势力——势力划分、关系、目标。覆盖率 = 已定义设定项数 / 必要设定项数。未覆盖的设定项在报告中列出。 | Draft | P2 |
| KS-28 | 角色关系网密度评估 | 评估角色关系网络的完备度。计算逻辑：(1) 核心角色间的关系建立率 = 已建立关系数 / 可能关系数（C(n,2)，n 为核心角色数）；(2) 孤立角色检测——与其他角色无关系的角色数量；(3) 关系类型多样性——已建立的关系是否覆盖多种类型（师徒/敌对/盟友等）。密度过低时预警。 | Draft | P2 |

### 3.3 知识库基础结构（KS-29 ~ KS-33）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| KS-29 | EntityIndex 实体倒排索引 | 构建全局实体倒排索引，支持 O(1) 查找。实体数据来源：(1) WorldBuilderAgent 创建的世界观实体；(2) CharacterAgent 管理的角色实体；(3) LLM 从正文中自动提取的实体。索引存储在内存中（JavaScript Map（前端内存），当前方案，后续可能根据架构评估调整），持久化到 PostgreSQL。支持按类型过滤（角色/地点/物品）。 | Draft | P0 |
| KS-30 | 世界观知识库 | 结构化管理世界观设定，包括：(1) 力量体系——等级、规则、限制；(2) 地理设定——地点、区域、关系；(3) 阵营势力——组织、目标、关系。与 WorldBuilderAgent（A-05）深度集成，设定变更通过 WorldBuilderAgent 统一管理。设定数据存储在 PostgreSQL，关系数据同步到 Neo4j。 | Draft | P0 |
| KS-31 | 角色知识库 | 与 CharacterAgent（A-06）五层记忆系统联动，存储和管理角色知识：(1) 角色基础信息（姓名、外貌、性格）；(2) 角色状态（当前情绪、位置、能力）；(3) 角色关系（与其他角色的关系）；(4) 角色记忆摘要（五层记忆的压缩视图）；(5) 角色弧线数据（与 B1 大纲系统联动）。角色知识库为 Agent 提供角色上下文查询服务。 | Draft | P0 |
| KS-32 | 作品知识库 | 管理作品级别的知识信息：(1) 章节摘要——每章的结构化摘要（LLM 自动生成）；(2) 事件索引——按时间线排列的事件列表；(3) 关键情节——重要情节节点和转折点。作品知识库为大纲系统（B1）、伏笔系统（B7）、节奏系统（B8）提供数据支撑。 | Draft | P0 |
| KS-33 | 知识库数据同步 | 知识库各子系统之间的数据同步机制：(1) EntityIndex 与 Neo4j 同步——实体创建/更新时自动同步到 Neo4j 图数据库；(2) 世界观设定与全文索引同步——设定变更时自动更新 PostgreSQL tsvector 索引；(3) 角色知识库与向量索引同步——角色信息变更时自动更新 pgvector 向量索引。同步采用事件驱动模式，通过事件总线异步执行。 | Draft | P1 |

## 4. 业务规则

### 4.1 搜索层规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-KS-01 | 搜索引擎自动路由 | 当用户输入包含精确实体名（匹配 EntityIndex）时，优先使用实体查找；当输入为自然语言描述时，优先使用向量搜索；当输入为关键词组合时，使用全文搜索。Agent 调用时根据任务类型自动选择引擎。 |
| BR-KS-02 | 搜索结果去重 | 多引擎并行搜索的结果必须去重（基于内容 ID 或文本相似度 > 0.95），同一内容只保留相关度最高的来源。 |
| BR-KS-03 | 搜索性能约束 | Agent 调用搜索接口的响应时间要求：实体查找 < 10ms，全文搜索 < 100ms，向量搜索 < 200ms，图查询 < 300ms，混合搜索 < 500ms。 |
| BR-KS-04 | 中文分词词典更新 | EntityIndex 中新增实体时，自动将实体名称和别名同步到 zhparser 自定义词典。词典更新后触发受影响章节的 tsvector 索引增量更新。 |
| BR-KS-05 | 向量模型一致性 | 所有向量化操作必须使用同一个 Embedding 模型。模型切换时，需全量重新向量化所有已索引内容。重新向量化期间，旧索引仍可使用。 |

### 4.2 知识库增强规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-KS-06 | 检索优先级 | ContextRouter 检索时严格遵循优先级：作品知识（canon）> 绑定参考（reference-work）> 全局参考（reference-global）。同优先级内按相关度排序。 |
| BR-KS-07 | 参考内容使用限制 | Agent 使用参考内容生成文本时，必须在输出中标注参考来源。参考内容不得作为 B2 一致性检查的事实基准。参考内容不得自动进入 EntityIndex（需作者确认后才可转为作品事实）。 |
| BR-KS-08 | 快照生成时机 | 自动快照在以下时机生成：(1) 作者手动标记卷完成；(2) 系统检测到卷结束标记（如"第 X 卷 完"）。每个卷最多生成 1 个自动快照。手动快照不限数量。 |
| BR-KS-09 | 快照存储策略 | 快照以 JSON 格式存储在 PostgreSQL（`knowledge_snapshots` 表），包含完整的设定状态数据。单快照大小限制 10MB。超过 50 个快照时，自动归档最早的快照（压缩为仅保留摘要）。 |
| BR-KS-10 | 一致性检查快照对齐 | B2 检查第 N 章内容时，使用 `get_state_at_chapter(N-1)` 获取事实基准。如第 N-1 章无精确快照，取最近的前置快照并叠加该快照后到第 N-1 章之间的增量变更。 |

### 4.3 知识完备度规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-KS-11 | knowledge_health 评分阈值 | 评分 ≥ 80 为"健康"（绿色），60-79 为"一般"（黄色），< 60 为"需关注"（红色）。评分变化超过 ±10 时触发趋势预警。 |
| BR-KS-12 | 必要设定项定义 | 必要设定项由 WorldBuilderAgent 根据作品类型和题材自动推荐，作者可调整。默认必要设定项：力量体系（如适用）、主要地点（≥ 5 个）、核心阵营（≥ 2 个）、核心角色（≥ 3 个）。 |
| BR-KS-13 | 元素活跃度计算 | B3 元素活跃度 = Σ(核心角色近 20 章出场次数 / 20) / 核心角色总数。出场次数包含直接提及（角色名、对话、动作）和间接提及（回忆、他人谈论、相关场景暗示）。活跃度 < 0.3 时预警"核心角色出场不足"。 |

## 5. 验收标准（AC）

### AC-KS-01：全文关键词搜索

**前置条件**：作品中已有 50 章以上内容，包含角色"苏瑶"、物品"神秘玉佩"、地点"青云山"。
