# AI/Agent 网文写作软件 — 前端验证版 PRD

> **版本**：v1.0
> **日期**：2026-04-24
> **来源**：基于 6 轮需求澄清（22 条优化建议）+ 原始 PRD v1.0（238 条需求）
> **定位**：前端验证版 PRD，基于原始全栈设计进行架构改造，聚焦"胖前端 + 瘦数据层" + 手动 LLM 模式

---

## 1. 项目愿景 (Vision)

以 AI/Agent 为中心的专业网文创作平台的**前端验证版**。通过"手动模式"（复制 prompt 到官网大模型对话获取回答）替代 API 调用，实现零 token 成本验证完整产品思路，同时保留精细控制每一步 Agent 调用的能力。

核心理念不变：**"作者为导演，AI 为剧组"** —— 作者掌控创作方向，AI 扮演专业角色，通过多 Agent 协作实现百万字级作品的设定一致性、角色真实感和叙事节奏把控。

### 1.1 与原始 PRD 的核心差异

| 维度 | 原始设计（全栈版） | 前端验证版 |
|------|-------------------|-----------|
| **架构** | Next.js + FastAPI + 5 个数据库 | Vite + React + Supabase + Neo4j |
| **后端** | 自建 FastAPI 后端 | 无自建后端，Supabase REST API + Edge Functions |
| **LLM 调用** | 通过 API 自动调用 | 手动模式（复制粘贴）+ API 模式（全局切换） |
| **部署** | Docker Compose（5 个数据库） | Docker Compose（Neo4j）+ Supabase Cloud |
| **数据库** | PostgreSQL + Milvus + Neo4j + Redis + SQLite | Supabase（PG + pgvector）+ Neo4j |
| **页面数** | 11 个 | 13 个（新增 Prompt 模板管理 + LLM 调用历史） |
| **目标** | 完整产品 | 验证思路 + 节省 token |

## 2. 核心价值 (Value Proposition)

- **用户价值**：零 token 成本体验完整的多 Agent 协作写作流程，精细控制每一步 LLM 交互，验证产品思路的可行性
- **技术价值**：验证"胖前端 + 瘦数据层"架构的可行性，为后续全栈版本积累前端组件和业务逻辑

## 3. 核心板块 (Core Modules)

### 3.1 手动 LLM 模式（核心改造）

**描述**：替代原设计的 API 自动调用，通过模态弹窗展示完整 prompt，用户复制到官网大模型对话获取回答后粘贴回来，系统自动解析并更新数据。

**关键特性**：
- 全局开关切换 API 模式 / 手动模式
- 逐步模式：每个 Agent 单独弹窗，精细控制
- 四层上下文可视化展示
- 多轮对话支持
- 双模式解析（自然语言 / JSON）
- 中断与恢复
- 关联功能：Prompt 模板管理（§3.4）、LLM 调用历史（§3.4）

### 3.2 多 Agent 协作体系（业务逻辑迁移到前端）

**描述**：将原后端的 Orchestrator + 7 个核心 Agent + 5 个协调层组件的业务逻辑迁移到前端 Service 层，通过统一 LLMAdapter 接口调用 LLM。

**关键特性**：
- 前端 Agent 调度编排
- Prompt 组装引擎
- 上下文装配（四层架构）
- 循环检测与中断
- 子 Agent 上下文隔离

### 3.3 创作工具集（9 个功能模块）

**描述**：覆盖网文创作的完整工具链。

**包含模块**：
- B1 大纲系统 → [outline-system.md](./features/outline-system.md)
- B2 隐含信息检测 + B3 因果链 → [consistency-check.md](./features/consistency-check.md)
- B4 长程风格一致性 → [style-consistency.md](./features/style-consistency.md)
- B5 多线叙事同步 → [multi-narrative.md](./features/multi-narrative.md)
- 角色模拟 + 记忆 + B6 → [character-memory.md](./features/character-memory.md)
- B7 伏笔协调层 → [foreshadow.md](./features/foreshadow.md)
- B8 节奏控制 → [rhythm-control.md](./features/rhythm-control.md)
- 技能系统 GEPA 闭环 → [skill-system.md](./features/skill-system.md)
- 知识库 + 搜索层 → [knowledge-search.md](./features/knowledge-search.md)

**关键特性**：
- TipTap 智能写作编辑器
- 九维健康度评估
- 四引擎搜索（全文 + 向量 + 实体 + 图关系）
- GEPA 技能闭环
- 介入度滑块控制

### 3.4 数据与基础设施

**描述**：Supabase（PostgreSQL + pgvector）作为主数据源，Neo4j 通过 Edge Functions 代理处理图关系查询。

**包含模块**：
- Prompt 模板管理 → [prompt-management.md](./features/prompt-management.md)
- LLM 调用历史 → [llm-history.md](./features/llm-history.md)

**关键特性**：
- Supabase 自动 CRUD API
- pgvector 替代 Milvus
- Neo4j Edge Function 代理
- Zustand 状态持久化
- 离线缓存与自动保存

## 4. 目标用户 & 核心场景 (User & Scenes)

### 4.1 目标用户

- **作者本人**：单人使用，验证 AI 辅助网文写作的产品思路。需要在零 API 成本下体验完整的多 Agent 协作写作流程。

### 4.2 核心场景

- **场景 1（手动写作）**：作者在写作工作台点击"AI 续写" → 系统组装完整 prompt 并在弹窗中展示 → 作者复制 prompt 到 ChatGPT 官网 → 获取回答后粘贴回弹窗 → 系统解析回答并插入编辑器 → ReviewerAgent 弹窗展示审校结果 → 作者确认采纳
- **场景 2（Prompt 调优）**：作者在 Prompt 模板管理页编辑 WriterAgent 的 prompt 模板 → 保存新版本 → 回到写作工作台触发写作 → 弹窗中预览组装后的完整 prompt → 发现上下文注入过多 → 在弹窗中手动取消部分上下文 → 复制精简后的 prompt 到官网
- **场景 3（多轮对话）**：WriterAgent 返回的正文不满意 → 作者在弹窗中输入追问"请把第二段改得更紧张一些" → 系统自动组装多轮上下文 → 再次复制到官网 → 获取改进后的回答 → 部分采纳第三段
- **场景 4（调用历史回溯）**：作者在 LLM 调用历史页搜索"WriterAgent 第7章" → 查看当时的完整 prompt 和回答 → 发现某个 prompt 模板效果好 → 复制该 prompt 到模板管理页保存为新版本

## 6. 关键业务流程 (Core Workflows)

### 6.1 手动模式写作流程（核心链路）

```
作者点击"AI 续写"
  → 前端 Orchestrator 识别意图
  → ContextRouter（手动弹窗）决定注入上下文
    → 用户复制 prompt 到官网 → 粘贴回答 → 前端解析
  → WriterAgent（手动弹窗）生成正文
    → 用户复制 prompt 到官网 → 粘贴回答 → 前端解析
    → [可选] 多轮对话追问
    → 用户部分/全部采纳 → 插入编辑器
  → ReviewerAgent（手动弹窗）审校
    → 用户复制 prompt 到官网 → 粘贴 JSON 回答 → 前端解析
  → RhythmDetector（手动弹窗）节奏检测
    → 用户复制 prompt → 粘贴回答 → 前端解析
  → StyleAgent（手动弹窗）风格优化
    → 用户复制 prompt → 粘贴回答 → 前端解析
  → 整合结果 → 更新数据 → 记录调用历史
```

### 6.2 API 模式写作流程（切换后）

```
作者点击"AI 续写"
  → 前端 Orchestrator 识别意图
  → ContextRouter（API 调用）决定注入上下文
  → WriterAgent（API 调用）生成正文
  → ReviewerAgent（API 调用）审校
  → RhythmDetector（API 调用）节奏检测
  → StyleAgent（API 调用）风格优化
  → 整合结果 → 更新数据 → 记录调用历史
```

### 6.3 Prompt 模板调优流程

```
作者打开 Prompt 模板管理页
  → 选择 WriterAgent 模板
  → 编辑模板内容 → 保存新版本
  → 回到写作工作台 → 触发写作
  → 弹窗中预览完整组装后的 prompt
  → 发现问题 → 返回模板管理页继续调优
```

### 6.4 大纲创建与版本管理流程

```
作者进入大纲编辑器
  → 创建全书粗纲（书名、类型、总卷数、总章数）
  → 创建卷纲（每卷的主题、角色出场、关键事件）
  → 创建章纲（每章的情节要点、情感走向、节奏标记）
  → [可选] OutlineAgent（手动/API）生成大纲建议
  → 情感曲线可视化检查
  → [可选] 预演引擎生成章节预览
  → 保存大纲 → 触发叙事线自动创建（B5 接口依赖）
```

### 6.5 角色创建与记忆初始化流程

```
作者进入角色管理页
  → 创建角色（基本信息、性格、能力、背景）
  → 定义角色关系（通过 Neo4j Edge Function）
  → 初始化五层语义记忆（核心/关系/能力/经历/情感）
  → [可选] CharacterAgent（手动/API）生成角色深度设定
  → 关系图谱可视化确认
  → 保存角色 → 触发一致性检查（B2）
```

### 6.6 知识库导入与索引构建流程

```
作者进入知识库管理页
  → 上传参考文件（txt/md/pdf）
  → 前端 FileReader API 解析文件内容
  → 分类归档（三级分类树）
  → 生成向量嵌入（pgvector，通过 Supabase Edge Function）
  → [可选] 完备度评估（LLMAdapter 调用 LLM 分析覆盖度）
  → 保存知识条目
```

### 6.7 伏笔埋设与追踪回收流程

```
作者在写作工作台标记伏笔
  → ForeshadowCoordinator（手动/API）识别伏笔元素
  → 伏笔进入"构思"状态
  → 作者确认埋设 → 状态转为"埋设"
  → 后续章节中伏笔进入"发酵"状态
  → [可选] 在某章节中暗示伏笔 → 状态转为"暗示"
  → 作者在某章节中揭示伏笔 → 状态转为"回收" → "完成"
  → 伏笔密度监控预警（超过阈值时通知）
```

### 6.8 技能沉淀 GEPA 闭环流程

```
作者完成一次写作操作
  → 系统记录写作行为（行为记录）
  → 章节保存后评估写作效果（效果评估）
  → 识别有效的写作策略（策略优化）
  → 沉淀为技能文件（技能沉淀）
  → 技能进入推荐队列，下次写作时自动推荐
```

### 6.9 隐含信息检测与修复流程

```
作者在写作工作台编辑章节
  → 编辑器内容变更 3 秒防抖
  → ConsistencyAgent（手动/API）实时检查
  → 检测到一致性问题（世界观/角色/能力/场景/视角）
  → TipTap 编辑器行内标记问题位置
  → 作者点击问题标记 → 查看详情和修复建议
  → 作者确认/否认问题 → 更新元素三态
```

## 7. 约束条件 (Constraints)

| # | 约束 | 说明 |
|---|------|------|
| 1 | 单人使用 | 无多用户/权限管理/注册登录 |
| 2 | 手动模式操作量 | 一次完整写作流程需 5-15 次复制粘贴 |
| 3 | Neo4j 网络延迟 | 通过 Edge Function 代理，有少量额外延迟 |
| 4 | pgvector 替代 Milvus | 大规模向量搜索性能可能下降（验证版可接受） |
| 5 | Supabase 免费额度 | 500MB 存储 + 5GB 带宽限制 |
| 6 | 桌面浏览器 | ≥1280px，不做移动端适配 |
| 7 | 一次性实现 | 所有功能一次性交付，不分阶段 |
| 8 | 前端代码注释 | 所有代码必须注释（用户要求） |

## 8. 项目边界 (Out of Scope)

- **不做多用户协作**：单人使用，无注册/登录/权限管理
- **不做移动端适配**：仅桌面浏览器
- **不做自建后端**：不写 FastAPI 代码
- **不做 Redis / Milvus / SQLite**：合并到 Supabase PostgreSQL
- **不做桌面应用**：不使用 Electron/Tauri
- **不做自动化部署 CI/CD**：手动部署
- **不做国际化**：仅中文
- **原 12 个后端技术方案**：不直接使用，业务逻辑迁移到前端 Service 层

## 9. 验收标准 (Acceptance Criteria)

> 详细验收标准见各功能独立文档，此处仅保留摘要。

### 9.1 手动 LLM 模式
- **AC-1**: 全局开关可切换 API 模式 / 手动模式，切换后所有 LLM 调用走对应模式
- **AC-2**: 手动模式下，每个 Agent 弹窗展示完整 prompt，支持一键复制
- **AC-3**: 粘贴回答后，自然语言模式可部分/全部采纳，JSON 模式自动解析结构化数据
- **AC-4**: 支持多轮对话，追问时自动组装上下文
- *详细文档*: [manual-llm-mode.md](./features/manual-llm-mode.md)

### 9.2 Prompt 模板管理
- **AC-1**: 可查看/编辑所有 Agent 的 prompt 模板
- **AC-2**: 支持版本保存和历史对比
- *详细文档*: [prompt-management.md](./features/prompt-management.md)

### 9.3 LLM 调用历史
- **AC-1**: 记录每次 LLM 调用的 Agent 类型、时间、prompt、回答
- **AC-2**: 支持按 Agent 类型、时间范围搜索筛选
- *详细文档*: [llm-history.md](./features/llm-history.md)

### 9.4 多 Agent 协作体系
- **AC-1**: Orchestrator 可正确调度 7 个 Agent 按写作流程执行
- **AC-2**: 循环检测在 N 轮内触发，中断后展示冲突信息
- *详细文档*: [agent-system.md](./features/agent-system.md)

### 9.5 上下文管理系统
- **AC-1**: 四层上下文架构正确分层，冷/温/热/动态压缩按规则工作
- **AC-2**: ContextBudgetManager 根据模型自动调整 token 预算
- *详细文档*: [context-management.md](./features/context-management.md)

### 9.6 B1 大纲系统
- **AC-1**: 支持三级大纲（全书粗纲/卷纲/章纲）的创建、编辑、删除和拖拽排序
- **AC-2**: 情感曲线可视化展示，支持按章节/卷维度查看
- **AC-3**: 预演引擎可基于大纲生成章节预览
- *详细文档*: [outline-system.md](./features/outline-system.md)

### 9.7 B2 隐含信息检测 + B3 因果链
- **AC-1**: 写作时实时检查世界观/铁事实/能力/身体/场景/视角的一致性
- **AC-2**: 章节级批量检查，生成一致性问题列表
- **AC-3**: 元素三态管理（确认/待确认/已否认）
- *详细文档*: [consistency-check.md](./features/consistency-check.md)

### 9.8 B4 长程风格一致性
- **AC-1**: 风格宪法定义和 20+6 维风格指标评估
- **AC-2**: AI 味检测和 5 级降级策略
- *详细文档*: [style-consistency.md](./features/style-consistency.md)

### 9.9 B5 多线叙事同步
- **AC-1**: 支持主线/支线/暗线管理，最多 50 条叙事线
- **AC-2**: 叙事线依赖 DAG 可视化和冲突检测
- *详细文档*: [multi-narrative.md](./features/multi-narrative.md)

### 9.10 角色模拟 + 记忆 + B6
- **AC-1**: 每角色独立 Agent 实例，五层语义记忆管理
- **AC-2**: 角色关系图谱可视化和情感履历时间线
- *详细文档*: [character-memory.md](./features/character-memory.md)

### 9.11 B7 伏笔协调层
- **AC-1**: 伏笔 8 状态机管理和状态转换
- **AC-2**: AI 自动识别伏笔和回收检测
- **AC-3**: 伏笔密度监控和依赖链 DAG 管理
- *详细文档*: [foreshadow.md](./features/foreshadow.md)

### 9.12 B8 节奏控制
- **AC-1**: 5 维节奏画像（叙事速度/对话比/动作比/情感强度/信息密度）
- **AC-2**: 节奏检测和建议引擎

- **规则 1**: Orchestrator 是唯一有权调度子 Agent 的组件

### 10.3 B1 大纲系统
- **规则 1**: 大纲修改后自动更新关联章节的摘要索引

### 10.4 B2 隐含信息检测 + B3 因果链
- **规则 1**: 实时检查在编辑器内容变更 3 秒防抖后触发

### 10.5 B4 长程风格一致性
- **规则 1**: 风格宪法修改后，后续章节自动应用新风格
- **规则 2**: AI 味检测结果缓存 24 小时，避免重复分析
- *详细文档*: [style-consistency.md](./features/style-consistency.md)

### 10.6 B5 多线叙事同步
- **规则 1**: 叙事线状态变更时通知所有关联章节
- **规则 2**: 最多支持 50 条叙事线，超出时提示归档

### 10.7 角色模拟 + 记忆 + B6
- **规则 1**: 角色记忆按五层分类，每层有独立的检索优先级

- *详细文档*: [character-memory.md](./features/character-memory.md)

### 10.8 B7 伏笔协调层
- **规则 1**: 伏笔从"埋设"到"回收"超过 50 章未处理则自动提醒

### 10.9 B8 节奏控制
- **规则 1**: 节奏分析在章节保存后自动触发
- **规则 2**: 连续 3 章节奏异常时触发通知

## 15. LLMAdapter 统一接口规范

### 15.1 接口定义

所有 LLM 调用必须通过 `LLMAdapter` 统一接口，支持手动模式和 API 模式两种实现。

```typescript
/**
 * LLM 调用请求
 */
interface LLMRequest {
  /** Agent 类型 */
  agentType: AgentType;
  /** 系统 prompt（模板） */
  systemPrompt: string;
  /** 用户指令 */
  userMessage: string;
  /** 上下文数据（四层装配结果） */
  context: AssembledContext;
  /** 期望的回答格式 */
  responseFormat: 'natural' | 'json';
  /** 模型配置 */
  modelConfig: ModelConfig;
  /** 关联的项目和章节 ID */
  projectId: string;
  chapterId?: string;
}

/**
 * LLM 调用响应
 */
interface LLMResponse {
  /** 调用状态 */
  status: 'success' | 'failed' | 'interrupted';
  /** 解析后的内容 */
  content: string;
  /** 结构化数据（JSON 模式） */
  structuredData?: Record<string, unknown>;
  /** 预估 token 数 */
  tokenCount: {
    prompt: number;
    completion: number;
    total: number;
  };
  /** 调用耗时（ms） */
  duration: number;
  /** 调用模式 */
  mode: 'manual' | 'api';
  /** 多轮对话历史 */
  conversationHistory?: ManualLLMTurn[];
}

/**
 * LLMAdapter 统一接口
 */
interface LLMAdapter {
  /** 发起 LLM 调用 */
  call(request: LLMRequest): Promise<LLMResponse>;
  /** 取消当前调用 */
  cancel(): void;
  /** 获取调用状态 */
  getStatus(): 'idle' | 'pending' | 'waiting_input' | 'processing';
}
```

### 15.2 两种实现

| 实现类 | 说明 | 调用方式 |
|--------|------|---------|
| `ManualLLMAdapter` | 手动模式：弹窗展示 prompt → 用户复制到官网 → 粘贴回答 → 前端解析 | 弹窗交互 |
| `ApiLLMAdapter` | API 模式：直接调用 LLM API（通过 Supabase Edge Function 代理） | HTTP 请求 |

### 15.3 模式切换

- 设置页面全局开关，切换后所有 `LLMAdapter` 实例使用对应实现
- 切换时进行确认提示（避免正在进行的调用中断）
- 切换状态持久化到 `localStorage`

## 17. Supabase 数据表概要（新增）

> 以下为前端验证版新增的数据表，用于支撑手动 LLM 模式、Prompt 模板管理和 LLM 调用历史功能。原有 26 张 PostgreSQL 表（参见原始数据库设计文档）保持不变，仅存储方式从自建 PG 迁移到 Supabase PG。

### 17.1 llm_call_history（LLM 调用历史）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| project_id | UUID | 关联项目 |
| chapter_id | UUID | 关联章节（可选） |
| agent_type | TEXT | Agent 类型（writer/reviewer/style/context_router 等） |
| mode | TEXT | 调用模式（manual/api） |
| prompt | TEXT | 完整 prompt 内容 |
| response | TEXT | 完整回答内容 |
| status | TEXT | 状态（success/failed/interrupted） |
| token_count | JSONB | Token 统计（{prompt, completion, total}） |
| version_fingerprint | TEXT | 版本指纹（SHA-256 hash） |
| conversation_history | JSONB | 多轮对话历史 |
| duration | INTEGER | 耗时（ms，手动模式为用户操作耗时） |
| created_at | TIMESTAMPTZ | 创建时间 |

| 字段 | 类型 | 说明 |

### 17.3 prompt_template_versions（Prompt 模板版本）

| 字段 | 类型 | 说明 |

## 18. Supabase Edge Functions（Neo4j 代理）

> 前端不直连 Neo4j，所有图查询通过 Supabase Edge Functions 代理，凭证存储在服务端。

| Function | 方法 | 说明 | 请求参数 | 返回格式 |
|----------|------|------|---------|---------|
| `neo4j-query` | POST | 执行 Cypher 查询，返回图数据 | `{ query: string, params?: object }` | `{ nodes: [], relationships: [] }` |
| `neo4j-relationship` | POST | 管理角色关系（创建/更新/删除） | `{ action: 'create'\|'update'\|'delete', data: object }` | `{ success: boolean, relationship: object }` |
| `neo4j-path` | POST | 查询角色关系路径 | `{ from: string, to: string, maxDepth?: number }` | `{ paths: [{ nodes: [], relationships: [] }] }` |

## 19. 风险与缓解措施

| # | 风险 | 影响 | 缓解措施 |
|---|------|------|---------|
| 1 | 手动模式操作繁琐（5-15 次复制粘贴） | 用户体验差，可能放弃使用 | 提供逐步模式精细控制 + 中断恢复 + 多轮对话减少重复 |
| 2 | 官网大模型返回格式不稳定 | JSON 解析失败 | 4 层容错解析 + 自然语言模式作为降级方案 |
| 3 | Supabase 免费额度不足 | 数据无法存储 | 用量监控 + 数据清理功能 + 可升级付费版 |
| 4 | 前端业务逻辑过重 | 代码复杂度高，维护困难 | Feature-Sliced Design 模块化 + 充分注释 + 单元测试 |
| 5 | Neo4j Edge Function 延迟 | 图查询响应慢 | 批量查询减少调用次数 + 前端缓存图数据 |
| 6 | pgvector 替代 Milvus 性能不足 | 大规模向量搜索慢 | 验证版数据量可控，可接受 |
