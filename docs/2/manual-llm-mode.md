# 手动 LLM 模式 - 功能需求文档

## 1. 功能概述

- **所属模块**：手动 LLM 模式（核心改造）
- **功能描述**：替代原设计的 API 自动调用，通过模态弹窗展示完整 prompt，用户复制到官网大模型对话获取回答后粘贴回来，系统自动解析并更新数据。支持全局切换 API 模式/手动模式。
- **优先级**：P0

---

## 2. 验收标准 (Acceptance Criteria)

### AC-1: 全局模式切换

- **Given** 用户在系统设置页面
- **When** 用户切换 LLM 调用模式为"手动模式"
- **Then** 所有后续 LLM 调用均通过手动弹窗进行，不再自动调用 API

### AC-2: Prompt 展示与复制

- **Given** 手动模式下触发 Agent 调用
- **When** 弹窗展示完整 prompt（含四层上下文可视化）
- **Then** prompt 按层级展示（系统指令 → 热存储 → 温存储 → 冷存储索引 → 用户指令），支持一键复制到剪贴板

### AC-3: Prompt 差异化标记

- **Given** prompt 中包含多个部分
- **When** prompt 展示时
- **Then** 各部分用 HTML 注释标记区分（`<!-- === 系统指令 === -->` 等），方便在官网中识别

### AC-4: 回答格式提示

- **Given** 手动弹窗打开
- **When** 用户准备粘贴回答
- **Then** 弹窗上方显示当前 Agent 期望的回答格式提示（如"请粘贴生成的正文内容"或"请粘贴 JSON 格式"）

### AC-5: 自然语言模式解析

- **Given** 用户粘贴自然语言回答（如 WriterAgent 的正文生成结果）
- **When** 系统解析回答
- **Then** 以预览/diff 视图展示，支持一键采纳全部、选中某几段单独采纳、手动编辑后采纳、完全丢弃

### AC-6: JSON 模式解析

- **Given** 用户粘贴 JSON 回答（如 ReviewerAgent 的审校结果）
- **When** 系统解析回答
- **Then** 自动解析结构化数据并更新对应数据

### AC-7: JSON 解析容错

- **Given** 用户粘贴的内容不是标准 JSON
- **When** 系统尝试解析
- **Then** 按优先级尝试：`JSON.parse` → 提取 ` ```json ` 代码块 → 提取第一个 `{` 到最后一个 `}` → 进入手动选择模式

### AC-8: 多轮对话

- **Given** 用户对 Agent 回答不满意
- **When** 用户在弹窗中输入追问内容
- **Then** 系统自动组装多轮上下文（历史 prompt + 回答 + 追问），生成新的 prompt 供复制

### AC-9: 部分采纳（AC-5 子场景）

- **Given** 自然语言模式下 Agent 返回正文（参见 AC-5）
- **When** 用户只想采纳其中某几段
- **Then** 支持选中特定段落单独采纳，未选中部分丢弃
- **注意**：本 AC 为 AC-5（自然语言模式解析）的子场景，重点验收"部分采纳"的交互体验

### AC-10: 中断与恢复

- **Given** 用户打开手动弹窗后未完成操作
- **When** 用户关闭弹窗或浏览器
- **Then** 未完成的调用保存到 localStorage，页面顶部显示待处理计数角标，重新打开后可恢复

### AC-11: 版本指纹检查

- **Given** 用户打开弹窗后项目数据被修改
- **When** 用户粘贴回答时
- **Then** 系统检测数据版本指纹，如已变更则提示"以下数据已变更：xxx，是否基于最新数据重新生成 prompt？"

### AC-12: 编辑器只读保护

- **Given** 手动模式弹窗打开
- **When** 用户尝试编辑 TipTap 编辑器内容
- **Then** 编辑器为只读状态，采纳回答后自动恢复可编辑

### AC-13: Token 预算显示

- **Given** prompt 组装完成
- **When** 弹窗展示 prompt
- **Then** 显示预估 token 数和当前模型的上下文窗口限制

### AC-14: 逐步 Agent 调用

- **Given** 写作协作流程涉及多个 Agent
- **When** 手动模式下执行流程
- **Then** 每个 Agent 单独弹窗，用户逐步控制和调整

### AC-15: ContextRouter 手动调用

- **Given** 手动模式下需要决定上下文注入
- **When** ContextRouter 被调用
- **Then** 也通过手动弹窗展示 prompt，用户粘贴回答后决定注入哪些上下文

## 3. 业务规则 (Business Rules)

| 编号 | 规则描述 |
|------|----------|
| BR-1 | 手动模式弹窗打开时，TipTap 编辑器设为只读状态，采纳后恢复 |
| BR-2 | 粘贴回答时进行版本指纹检查（基于关键数据的 hash），数据已变更则提示 |
| BR-3 | JSON 解析按优先级尝试 4 层容错：`JSON.parse` → 提取 ` ```json ` 代码块 → 提取第一个 `{` 到最后一个 `}` → 进入手动选择模式 |
| BR-4 | 自然语言模式默认展示 diff 预览，需用户显式采纳 |
| BR-5 | 多轮对话历史最多保留 10 轮，超出时丢弃最早的轮次 |
| BR-6 | 中断恢复的调用数据保留 7 天，超时自动清理 |
| BR-7 | Prompt 中的 HTML 注释标记不影响 LLM 生成质量（大部分官网大模型会忽略） |
| BR-8 | Token 预算根据设置页面配置的"当前使用模型"自动计算 |
| BR-9 | 逐步模式下，Agent 按写作协作流程顺序执行，用户可跳过非关键 Agent |

## 4. 用户故事 (User Stories)

| 编号 | 用户故事 |
|------|----------|
| US-1 | 作为作者，我希望在设置中一键切换手动/API 模式，以便根据需要选择调用方式 |
| US-2 | 作为作者，我希望在弹窗中看到完整的 prompt 和四层上下文装配过程，以便精确控制每次 LLM 调用的输入 |
| US-3 | 作为作者，我希望 prompt 中有清晰的标记区分各部分，以便在官网对话中快速定位 |
| US-4 | 作为作者，我希望弹窗告诉我期望的回答格式，以便返回符合系统要求的内容 |
| US-5 | 作为作者，我希望正文生成结果支持部分采纳，以便只保留满意的段落 |
| US-6 | 作为作者，我希望支持多轮对话追问，以便在不满意的回答基础上继续优化 |
| US-7 | 作为作者，我希望未完成的调用可以暂存和恢复，以便处理临时中断 |
| US-8 | 作为作者，我希望看到 prompt 的预估 token 数，以便避免超出官网模型的上下文限制 |

## 5. 界面要求 (UI Requirements)

### 5.1 手动模式弹窗

- **组件类型**：模态对话框（Modal）
- **尺寸**：宽度 `80vw`，最大宽度 `1200px`
- **层级**：最高 z-index，覆盖页面内容

### 5.2 弹窗布局

```
+------------------------------------------------------------------+
|  [Agent 名称] - 手动 LLM 调用                          [关闭 X] |
+------------------------------------------------------------------+
|                        |                                          |
|   Prompt 展示区        |          回答粘贴区                      |
|   (左侧 50%)          |          (右侧 50%)                      |
|                        |                                          |
|  [期望格式提示]         |  [格式提示：请粘贴 JSON 格式]            |
|                        |                                          |
|  ▼ 系统指令 (120 tok)  |  +------------------------------------+ |
|    ...内容...          |  |                                    | |
|                        |  |     多行文本输入框                   | |
|  ▼ 热存储 (340 tok)    |  |                                    | |
|    ...内容...          |  |                                    | |
|                        |  +------------------------------------+ |
|  ▶ 温存储 (0 tok)      |                                          |
|                        |  [Token 预算: 1,280 / 128,000]           |
|  ▶ 冷存储索引 (0 tok)  |                                          |
|                        |  +------------------------------------+ |
|  ▼ 用户指令 (56 tok)   |  | 追问输入框              [发送追问]  | |
|    ...内容...          |  +------------------------------------+ |
|                        |                                          |
|  [Token 预算: 516 tok] |  [采纳全部] [部分采纳] [丢弃]            |
|  [一键复制 Prompt]     |                                          |
+------------------------------------------------------------------+
```

### 5.3 各区域说明

| 区域 | 说明 |
|------|------|
| Prompt 展示区 | 按层级可展开/折叠，每层有标题和 token 计数，支持一键复制 |
| 回答粘贴区 | 顶部显示期望格式提示，下方为多行文本输入框 |
| 底部操作栏 | 左侧：复制 prompt 按钮；右侧：采纳/丢弃按钮 |
| 追问输入框 | 位于回答粘贴区下方，支持输入追问内容触发多轮对话 |
| 待处理角标 | 页面顶部导航栏显示红色圆点 + 数字，点击可打开暂存列表 |

### 5.4 交互状态

- **初始状态**：弹窗打开，左侧展示 prompt，右侧等待粘贴
- **已粘贴状态**：右侧显示解析结果预览（diff 视图或 JSON 结构化展示）
- **多轮对话状态**：下方展开追问区域，左侧 prompt 自动更新为多轮上下文
- **中断恢复状态**：导航栏角标高亮，点击弹出暂存调用列表

## 6. 数据要求 (Data Requirements)

### 6.1 输入数据

| 数据项 | 说明 | 来源 |
|--------|------|------|
| Agent 类型 | 当前调用的 Agent 标识（WriterAgent、ReviewerAgent 等） | 流程引擎 |
| 上下文数据 | 四层上下文装配结果（热存储、温存储、冷存储索引） | ContextRouter |
| 用户指令 | 当前步骤的用户输入或系统预设指令 | Prompt 模板引擎 |
| 当前模型配置 | 模型名称、上下文窗口大小等 | 设置页面 |

### 6.2 输出数据

| 数据项 | 说明 | 格式 |
|--------|------|------|
| 结构化结果 | Agent 返回的 JSON 结构化数据 | JSON |
| 自然语言文本 | Agent 返回的正文内容 | Markdown / 纯文本 |

### 6.3 存储要求

| 存储位置 | 数据内容 | 生命周期 |
|----------|----------|----------|
| Supabase `llm_call_history` 表 | LLM 调用记录（含 prompt、回答、耗时等） | 永久 |
| localStorage | 中断暂存的调用数据（prompt、状态、时间戳） | 7 天自动清理 |

### 6.4 版本指纹

- **计算方式**：对关键数据（当前章节内容、角色状态、大纲结构等）生成 SHA-256 hash
- **存储位置**：随调用记录一起存储
- **检查时机**：用户粘贴回答时，重新计算 hash 并与存储值比对

## 7. 依赖关系 (Dependencies)

### 7.1 前置依赖

| 依赖模块 | 说明 |
|----------|------|
| LLMAdapter 统一接口 | 手动模式作为 LLMAdapter 的一种实现（ManualLLMAdapter），与 API 模式（APILLMAdapter）共享统一接口 |
| ContextRouter 上下文装配 | 提供四层上下文的装配能力，手动模式需展示装配结果 |
| Prompt 模板引擎 | 负责将上下文数据和用户指令组装为完整 prompt |

### 7.2 后续影响

| 影响模块 | 说明 |
|----------|------|
| Agent 协作流程 | 所有 Agent 调用均需适配手动模式，支持逐步执行 |
| 大纲生成 | OutlineAgent 调用需支持手动模式 |
| 正文写作 | WriterAgent 调用需支持手动模式 |
| 审校系统 | ReviewerAgent 调用需支持手动模式 |
| 一致性检查 | ConsistencyAgent 调用需支持手动模式 |
| 伏笔管理 | ForeshadowAgent 调用需支持手动模式 |

### 7.3 依赖关系图

```
设置页面（模式切换）
       │
       ▼
  LLMAdapter 统一接口
       │
       ├── APILLMAdapter（API 模式）
       │
       └── ManualLLMAdapter（手动模式）
              │
              ├── Prompt 展示与复制
              ├── 回答粘贴与解析
              │     ├── 自然语言解析（diff 预览 + 部分采纳）
              │     └── JSON 解析（4 层容错）
              ├── 多轮对话管理
              ├── 中断暂存与恢复
              └── 版本指纹检查
```
