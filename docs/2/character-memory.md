## 1. 功能概述

本功能定义了 AI 辅助长篇小说创作平台的角色模拟与记忆系统，以及 B6 角色状态桥梁层。系统为每个角色创建独立的 Agent 实例，赋予其内部状态模型、五层记忆结构和情感履历追踪能力，使角色在百万字级长篇作品中保持行为一致性和情感真实性。

功能分为四个核心部分：

1. **角色模拟 Agent（CH-01~CH-06）：** 每个角色拥有独立 Agent 实例，包含内部状态模型（情绪、情感触发器、行为边界、情感累积值）和 `react_to()` 反应接口，输出结构化的 action + justification + internal_monologue。通过动态唤醒策略管理资源消耗——核心角色常驻、重要角色按需唤醒、龙套不需要 Agent。

2. **角色记忆系统（CH-07~CH-11）：** 五层记忆结构（事实/情感/关系/技能经验/目标动机）+ LLM 智能遗忘机制 + 五种触发机制 + 主观/客观/读者三层信息分离。不设硬限制，由 ContextBudgetManager 统一管控。

3. **增强记忆系统（决策 #34~#38）：** 在基础记忆之上增加主动持久化、情景记忆（Episodic）、记忆再激活（Reinstatement）、冲突记忆消解和关联记忆网络（Neo4j）五大增强能力，与基础记忆系统协同工作。

4. **B6 角色状态桥梁层（B6-01~B6-06）：** 作为独立模块层组件，负责角色运行时状态的持久化、大纲与角色的衔接、弧线数据管理和事件驱动集成，是 Agent 层与基础设施层之间的桥梁。

### 核心设计原则

- **角色独立性**：每个角色拥有独立的 Agent 实例、内部状态和记忆空间，互不干扰
- **LLM 优先**：记忆提取、遗忘决策、情感判断均由 LLM 执行，算法做数据管理和存储
- **动态资源管理**：不设硬性 token 限制，通过唤醒策略和 ContextBudgetManager 灵活管控
- **三层信息分离**：区分角色认为的（主观）、实际发生的（客观）、读者知道的（全知）三个信息层
- **记忆动态平衡**：遗忘衰减与再激活形成动态平衡，避免记忆无限膨胀或过早丢失

### 3.2 角色记忆系统（CH-07 ~ CH-11）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| CH-07 | 五层记忆结构 | 角色记忆分为五个层级，全部由 LLM 自动提取（决策 #7）：(1) 事实记忆：角色知道的信息、经历的事件；(2) 情感记忆：角色对人物/事件/地点的情感态度；(3) 关系记忆：角色与其他角色的关系及变化历史；(4) 技能/经验记忆：角色习得的技能和积累的经验；(5) 目标/动机记忆：角色的短期目标和长期动机。每层记忆独立存储，支持分层检索。 | ✅ 已设计 | P0 |
| CH-08 | 遗忘机制 | LLM 智能衰减（决策 #8）。以下为参考公式，LLM 可根据上下文动态调整权重（决策 #8：LLM 智能衰减）：`recallability = emotion_intensity * 0.6 + importance * 0.2 + time_decay * 0.2`。其中 `emotion_intensity` 为记忆的情感强度（0-1），`importance` 为记忆重要性（0-1，由 LLM 评估），`time_decay` 为时间衰减因子（基于章节数，LLM 综合判断）。可回忆度低于阈值（默认 0.3）的记忆进入"模糊"状态，LLM 在需要时以不确定的语气引用。 | ✅ 已设计 | P0 |
| CH-09 | 触发机制 | 五种记忆触发方式：(1) 场景触发：角色回到曾经到过的地点；(2) 人物触发：遇到记忆中的人物；(3) 话题触发：对话涉及记忆中的话题；(4) 感官触发：特定感官刺激（声音、气味、触感等）；(5) 情境触发：当前情境与记忆情境相似。触发后由 LLM 决定是否激活记忆及如何表达。 | ✅ 已设计 | P1 |
| CH-10 | 存储规模管理 | 不设硬性 token 限制（决策 #21），由 ContextBudgetManager 统一管控。记忆存储在关系数据库（PostgreSQL）中，通过四层上下文架构（冷/温/热/动态压缩）管理注入量。高频记忆访问数据按时间分区存储，旧数据自动压缩归档。 | ✅ 已设计 | P0 |
| CH-11 | 主观记忆 vs 客观事实 | 区分三层信息：(1) 角色主观认知：角色认为的事实（可能错误或片面）；(2) 客观事实：实际发生的事情（由系统记录）；(3) 读者全知视角：读者知道但角色不知道的信息。三层信息独立存储，写作时根据叙事视角选择注入哪层信息。角色主观认知与客观事实的偏差可用于制造叙事张力。 | ✅ 已设计 | P1 |

### 3.3 增强记忆系统（决策 #34 ~ #38）

> **注意**：增强记忆系统在基础记忆系统之上提供高级能力，与 CH-07~CH-11 的基础记忆协同工作。以下需求为独立增强模块，不替代基础记忆功能。

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| #34 | 主动持久化 | LLM 在写作过程中主动评估信息的持久化价值。当检测到对角色未来行为有重要影响的信息时（如关键事件、关系变化、新技能习得），自动将信息从工作记忆（热存储）转入长期记忆（温/冷存储）。评估维度：信息独特性、情感关联度、对未来情节的潜在影响。作者可查看和调整持久化决策。 | ✅ 已设计 | P1 |
| #35 | 情景记忆（Episodic） | 角色不仅"知道"事实，还能"回忆起当时的感受和细节"。每条情景记忆包含六个维度：(1) 时间：具体时间或时间段；(2) 地点：具体场景描述；(3) 人物：参与的角色列表；(4) 感官：视觉/听觉/嗅觉/触觉/味觉等感官细节；(5) 情感：当时的情感状态和强度；(6) 摘要：事件概要。用于内心独白、对话回忆、意识流写作等场景。由 LLM 在章节完成后自动提取。 | ✅ 已设计 | P1 |
| #36 | 记忆再激活（Reinstatement） | 被重新提起的记忆强度回升，与遗忘机制（CH-08）形成动态平衡。再激活规则：首次再激活 `recallability += 0.3`，第二次 `+= 0.2`，第三次 `+= 0.1`，之后每次 `+= 0.05`（递减效应）。再激活触发条件：记忆被角色主动回忆、被其他角色提及、或通过关联记忆网络被间接激活。再激活记录写入 `character_memories` 表（通过 `access_count`、`last_accessed`、`activation_score` 字段追踪再激活行为，无独立日志表）。 | ✅ 已设计 | P1 |
| #37 | 冲突记忆消解 | 当角色获得与已有记忆矛盾的新信息时，自动触发消解流程。消解策略按优先级：(1) 时间优先：新信息覆盖旧信息（默认策略）；(2) 来源优先：可信来源的信息优先（如亲历 > 听说 > 猜测）；(3) 认知偏差标记：标记为"角色认知偏差"，保留两条记忆但标注矛盾；(4) 作者裁决：提交作者决定保留哪条。与 B2 一致性检查联动，当矛盾涉及世界观硬规则时自动上报。 | ✅ 已设计 | P2 |
| #38 | 关联记忆网络（Neo4j + LLM） | 基于 Neo4j 图数据库构建角色记忆的联想网络。五种关联类型：(1) 共现关联：同时出现在同一场景的记忆；(2) 因果关联：存在因果关系的记忆；(3) 情感关联：引发相似情感的记忆；(4) 时间关联：时间上相近的记忆；(5) 感官关联：涉及相同感官体验的记忆。关联发现分两阶段：写作后自动发现（异步批处理）+ 实时推理补充（写作时 LLM 按需联想）。联想深度由 LLM 根据当前叙事需要动态控制，非固定值。 | ✅ 已设计 | P2 |

| B6-04 | 角色弧线数据管理 | 管理角色弧线的结构化数据，包含三张核心表：(1) `character_arcs`：角色弧线定义（角色 ID、弧线名称、起始阶段、目标阶段）；(2) `arc_phases`：弧线阶段（阶段名称、描述、情感目标、预期行为变化）；(3) `arc_milestones`：弧线里程碑（里程碑名称、触发条件、完成状态、完成章节）。支持多角色、多弧线并行管理。 | ✅ 已设计 | P1 |
| B6-05 | 里程碑触发机制 | 伏笔回收可触发角色弧线里程碑更新。当 B7 伏笔协调层检测到伏笔回收事件时，通过 CrossModuleEventBus 发送 `FORESHADOW_RESOLVED` 事件，B6 监听该事件并检查是否有关联的弧线里程碑。如果伏笔回收满足里程碑触发条件，自动更新里程碑状态为"已完成"并记录完成章节。 | ✅ 已设计 | P2 |
| B6-06 | 事件驱动集成 | B6 桥梁层通过 CrossModuleEventBus 监听以下事件并做出响应：(1) `OUTLINE_UPDATED`：大纲更新时，检查受影响角色的弧线数据是否需要同步；(2) `FORESHADOW_RESOLVED`：伏笔回收时，检查里程碑触发条件（B6-05）；(3) `CHAPTER_COMPLETED`：章节完成时，触发角色状态持久化（B6-01）；(4) `CHARACTER_STATE_CHANGED`：角色状态变更时，更新 `global_state`。 | ✅ 已设计 | P1 |

## 4. 业务规则

### 4.1 角色模拟规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-CH-01 | 每个角色最多创建一个 CharacterAgent 实例，不得重复创建 |
| BR-CH-02 | react_to() 接口的输出必须包含 action、justification、internal_monologue 三个字段，缺一不可 |
| BR-CH-03 | 角色的 internal_monologue 可以与 action 不一致（如口是心非），但 justification 必须能解释 action |
| BR-CH-04 | 情感累积值范围为 -1.0 到 1.0，超出范围自动截断 |
| BR-CH-05 | 核心角色列表由作者手动指定，默认为主角和前 4 个主要角色 |
| BR-CH-06 | 龙套角色的行为由 LLM 按需生成，不创建持久化 Agent 实例 |

### 4.2 记忆管理规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-CH-07 | 五层记忆全部由 LLM 自动提取（决策 #7），不依赖手动标记 |
| BR-CH-08 | 遗忘机制以 LLM 智能判断为主（决策 #8），参考公式 `recallability = emotion_intensity * 0.6 + importance * 0.2 + time_decay * 0.2` 作为辅助基准。LLM 可根据角色性格、情节重要性、叙事需要等因素动态调整权重 |
| BR-CH-09 | 可回忆度 < 0.3 的记忆标记为"模糊"，LLM 以不确定语气引用（如"他似乎记得..."） |
| BR-CH-10 | 角色记忆不设硬性 token 上限（决策 #21），由 ContextBudgetManager 管控注入量 |
| BR-CH-11 | 主观记忆与客观事实的偏差由 LLM 自动识别，偏差超过阈值时标记"认知偏差" |
| BR-CH-12 | 三层信息（主观/客观/全知）的注入由叙事视角决定：第一人称仅注入主观+客观，第三人称全知可注入全知层 |

### 4.3 增强记忆规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-CH-13 | 主动持久化的评估由 LLM 在写作过程中实时执行，不阻塞写作流程 |
| BR-CH-14 | 情景记忆的六个维度（时间/地点/人物/感官/情感/摘要）必须完整，缺失维度标记为"模糊" |
| BR-CH-15 | 记忆再激活的递减幅度固定：+0.3 → +0.2 → +0.1 → +0.05（之后固定 +0.05） |
| BR-CH-16 | 再激活后的可回忆度不超过 1.0 |
| BR-CH-17 | 冲突记忆消解默认使用"时间优先"策略，作者可覆盖为其他策略 |
| BR-CH-18 | 关联记忆网络的联想深度由 LLM 动态控制，单次联想不超过 3 层 |
| BR-CH-19 | 关联发现的异步批处理在章节完成后 60 秒内启动，不影响写作流程 |

### 4.4 B6 桥梁层规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-CH-20 | 角色运行时状态在每次会话结束时自动持久化，不得丢失 |
| BR-CH-21 | 状态恢复时，如果数据库中的状态版本与当前大纲版本不匹配，提示作者确认 |
| BR-CH-22 | get_character_arc_progress() 返回的弧线偏差度超过 0.5 时，标记为"弧线偏离预警" |
| BR-CH-23 | 里程碑触发条件由 B6-04 的 `arc_milestones.trigger_condition` 字段定义，支持表达式 |
| BR-CH-24 | 事件驱动集成中，OUTLINE_UPDATED 事件的响应必须在 5 秒内完成 |

## 5. 验收标准（AC）

### AC-CH-01：独立角色 Agent 创建与运行

- [ ] **AC-CH-01-03**：核心角色（默认主角 + 前 4 主要角色）在项目启动时自动创建 Agent 并常驻内存
- [ ] **AC-CH-01-04**：重要角色在当前场景涉及时自动唤醒，场景结束后 30 秒内进入休眠状态
- [ ] **AC-CH-01-05**：龙套角色不创建 Agent 实例，LLM 按需生成行为，响应时间 < 2 秒

### AC-CH-02：react_to() 接口

**前置条件：** 角色 Agent 已创建并初始化。

- [ ] **AC-CH-02-01**：输入事件"林逸的好友被杀害"后，react_to() 返回结构化 JSON，包含 action、justification、internal_monologue 三个字段
- [ ] **AC-CH-02-02**：action 字段描述角色的外在行为（说的话、做的事），与角色性格一致
- [ ] **AC-CH-02-03**：justification 字段解释行为理由，引用角色的性格特征和当前状态
- [ ] **AC-CH-02-04**：internal_monologue 字段展示角色内心真实想法，可以与 action 不一致
- [ ] **AC-CH-02-05**：react_to() 响应时间 < 3 秒（含 LLM 调用）

### AC-CH-03：情感累积与衰减

**前置条件：** 角色已经历至少 5 个章节。

- [ ] **AC-CH-03-01**：角色经历正面事件后，emotion_accumulator 正面值增加，增量由 LLM 根据事件影响评估
- [ ] **AC-CH-03-02**：角色经历负面事件后，emotion_accumulator 负面值增加

- [ ] **AC-CH-03-04**：情感履历时间线正确展示各章节的情感变化，支持按情感类型筛选
- [ ] **AC-CH-03-05**：LLM 智能衰减生效，10 章前的强烈情感在无再激活的情况下可回忆度降至 0.3 以下

### AC-CH-04：五层记忆结构

**前置条件：** 角色已经历至少 10 个章节。

- [ ] **AC-CH-04-01**：系统能展示角色的五层记忆分类视图，每层记忆数量和内容可独立查看
- [ ] **AC-CH-04-02**：事实记忆包含角色经历的事件和知道的信息，由 LLM 自动提取
- [ ] **AC-CH-04-03**：情感记忆包含角色对特定人物/事件/地点的情感态度，含正负面标记
- [ ] **AC-CH-04-04**：关系记忆包含角色与其他角色的关系及变化历史，支持关系图谱可视化

- [ ] **AC-CH-04-06**：目标/动机记忆包含角色的短期目标和长期动机，支持目标完成度追踪

### AC-CH-05：遗忘机制

**前置条件：** 角色有至少 50 条记忆记录。

- [ ] **AC-CH-05-01**：验证 LLM 衰减结果的合理性：LLM 衰减结果与参考公式 `recallability = emotion_intensity * 0.6 + importance * 0.2 + time_decay * 0.2` 的偏差在合理范围内，且符合叙事逻辑（如角色性格、情节重要性等因素被合理考虑）
- [ ] **AC-CH-05-02**：可回忆度 < 0.3 的记忆在角色回忆时以不确定语气表达（如"他似乎记得..."、"大概是..."）

|------|------|
| CharacterAgent | 角色代理，每个角色独立的 Agent 实例，维护角色的状态和行为逻辑 |

| react_to() | 角色反应接口，输入事件输出结构化反应（action + justification + internal_monologue） |
| 五层记忆 | 事实记忆、情感记忆、关系记忆、技能/经验记忆、目标/动机记忆 |
| 可回忆度 | recallability，记忆被角色准确回忆的概率，（参考公式）公式：情感强度x0.6 + 重要性x0.2 + 时间衰减x0.2 |
| 情景记忆 | Episodic Memory，包含时间/地点/人物/感官/情感/摘要的完整场景记忆 |
| 记忆再激活 | Reinstatement，被重新提及的记忆强度回升，与遗忘形成动态平衡 |

| 弧线偏差度 | 角色实际发展轨迹与大纲规划的弧线之间的偏离程度（0-1） |
