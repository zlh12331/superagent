# 技能系统（GEPA 闭环）

> **所属模块：** 核心基础设施（独立模块，与 Agent 系统深度集成）
> **需求来源：** 需求澄清记录决策 #29 ~ #47，参考 Hermes Agent 技能系统
> **状态：** Draft
> **版本：** v1.0
> **最后更新：** 2026-04-21

---

## 1. 功能概述

技能系统是 AI/Agent 网文写作软件的核心学习与进化模块，借鉴 Hermes Agent 的技能管理理念，实现"越写越强"的系统进化能力。系统通过 GEPA 闭环（行为记录 -> 效果评估 -> 策略优化 -> 技能沉淀）自动从写作过程中提炼和优化技能，使 AI 的写作能力随使用不断精进。

系统核心能力包括：

1. **自动沉淀（决策 #29）：** 写作任务完成后，LLM 自动从 WriterAgent 的完整上下文中提炼技能文件（Markdown 格式），无需作者手动总结。

2. **GEPA 闭环优化（决策 #39）：** 四步闭环机制——记录 WriterAgent 的完整行为上下文，基于作者采纳率和 ReviewerAgent 评分评估效果，根据评估结果优化技能内容，将优化后的技能写入技能库。每次写作后自动运行。

3. **渐进式披露：** 技能内容按三级深度组织——Level 0 概要（~3K tokens）用于 Agent 调度时的快速匹配，Level 1 完整内容用于写作时的上下文注入，Level 2 深入参考用于复杂场景的详细指导。

4. **技能分类体系（决策 #40）：** 6 大分类——写作技巧 / 检查规则 / 风格模板 / 大纲策略 / 角色塑造 / 自定义，支持作者扩展。

5. **技能自动推荐（决策 #41）：** Orchestrator 调度 WriterAgent 时，自动推荐与当前场景匹配的技能，作者可覆盖或忽略。

6. **技能组合 Composition（决策 #42）：** 经常一起使用的技能自动组合为"复合技能"（如"战斗场景+情感爆发"），由 GEPA 闭环发现组合关系。

7. **技能变体 Variants（决策 #43）：** 基础技能可衍生风格变体（如"对话写作"->"古风对话"/"反派对话"/"温馨对话"），LLM 自动发现并创建。

8. **反面技能 Anti-patterns（决策 #44）：** GEPA 闭环中低分结果（ReviewerAgent 评分 <60）沉淀为"反面技能"，记录"什么不该做"，避免重复犯错。

9. **技能衰减 Decay（决策 #45）：** 长期不被推荐或使用的技能逐渐降低权重，避免过时技能干扰写作质量。

10. **技能版本追踪（决策 #46）：** 技能在 GEPA 优化中保留版本历史（v1.0 -> v1.1 -> v2.0），作者可回溯进化轨迹和回滚。

11. **跨作品技能迁移（决策 #47）：** 作品 A 沉淀的技能可导出为技能包，导入作品 B 时自动适配新世界观/角色/设定。

12. **手动管理：** 作者可创建、编辑、分享、导入技能，完全掌控技能库内容。

13. **技能存储：** 本地文件系统（Markdown）+ PostgreSQL tsvector 全文搜索，兼顾可读性和检索效率。<!-- 注：Supabase 为应用层数据存储方案（Markdown 内容存储在 skills.content JSONB 列中），非独立文件系统管理。数据库层通过 Supabase skills 表（PostgreSQL）存储元数据，PostgreSQL skill_search_index 表提供全文搜索能力。 -->

### 核心设计原则

- **自动沉淀，人工审核：** 技能自动提炼，但新技能首次使用需作者确认，确保质量
- **GEPA 驱动进化：** 所有技能优化都基于实际写作效果的反馈闭环，而非主观判断
- **渐进式披露：** 按需加载不同深度的技能内容，控制 Token 消耗
- **开放可扩展：** 支持手动创建和导入，不封闭为纯自动系统
- **作品隔离：** 技能与作品绑定，跨作品迁移需显式操作

## 3. 功能需求

### 3.1 自动沉淀（决策 #29）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| SK-01 | 写作后自动提炼 | 每次 WriterAgent 完成写作任务后，系统自动调用 LLM 从完整上下文（Prompt、生成内容、角色状态、工具调用记录）中提炼潜在技能。提炼结果生成 Markdown 格式的技能文件草稿，状态为 `draft`。 | Draft | P0 |
| SK-02 | 技能文件格式 | 技能文件为标准 Markdown 格式，包含以下元数据 Front Matter：`id`（唯一标识）、`name`（技能名称）、`category`（分类）、`tags`（标签列表）、`version`（版本号）、`created_at`（创建时间）、`updated_at`（更新时间）、`source_chapter`（来源章节）、`usage_count`（使用次数）、`adoption_rate`（采纳率）、`avg_score`（平均评分）、`weight`（推荐权重）。正文包含：技能描述、适用场景、具体指导、示例片段、注意事项。 | Draft | P0 |

### 3.2 GEPA 闭环优化（决策 #39）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| SK-04 | G - 行为记录（Gather） | 记录 WriterAgent 每次写作的完整上下文，包括：(1) 输入 Prompt（系统指令 + 用户指令 + 注入上下文）；(2) 角色状态快照（当前情感、目标、关系）；(3) 工具调用记录（调用了哪些工具、参数、返回值）；(4) 生成内容（最终输出文本）；(5) 使用的技能列表（哪些技能被注入了上下文）。记录以 `BehaviorRecord` 数据结构持久化，保留 30 天。 | Draft | P0 |
| SK-05 | E - 效果评估（Evaluate） | 基于两个维度评估写作效果：(1) **作者采纳率**：生成内容中被作者保留的比例（逐段对比，保留 = 采纳，修改 = 部分采纳，删除 = 不采纳）；(2) **ReviewerAgent 评分**：ReviewerAgent 对生成内容的多维度评分（0-100）。综合效果分 = 采纳率 x 0.4 + ReviewerAgent 评分/100 x 0.6（初始建议权重，待技术设计阶段根据实际数据校准）。评估结果关联到使用的每个技能。 | Draft | P0 |
| SK-06 | P - 策略优化（Plan） | 根据效果评估结果优化技能内容。优化策略：(1) **正向优化**：综合效果分 >80 的技能，LLM 分析成功因素，提炼为更精确的指导规则，生成新版本；(2) **负向优化**：ReviewerAgent 评分 <60 的技能（与决策 #44 一致），LLM 分析失败原因，生成反面技能（Anti-pattern），综合效果分作为辅助参考；(3) **微调优化**：综合效果分 60-80 的技能，LLM 根据具体反馈微调指导内容。优化频率：每累计 5 次使用后触发一次评估，达到优化阈值后触发优化。 | Draft | P0 |
| SK-07 | A - 技能沉淀（Act） | 优化后的技能写入技能库：(1) 正向优化生成新版本（版本号递增，如 v1.0 -> v1.1），保留旧版本历史；(2) 负向优化生成反面技能（标记 `type: anti_pattern`），关联到原技能；(3) 微调优化直接更新当前版本。所有变更记录变更日志（changelog），包含优化依据和具体变更内容。 | Draft | P0 |
| SK-08 | GEPA 自动触发 | 每次写作任务完成后自动运行 GEPA 闭环。流程：写作完成 -> 行为记录（G） -> 效果评估（E） -> 判断是否达到优化阈值 -> 策略优化（P） -> 技能沉淀（A）。整个流程异步执行，不阻塞写作流程。 | Draft | P0 |

### 3.7 技能变体 Variants（决策 #43）

| 编号 | 需求 | 说明 | 状态 | 优先级 |
|------|------|------|------|--------|
| SK-21 | 变体自动发现 | LLM 在技能优化过程中，分析技能在不同场景下的效果差异。当同一技能在特定子场景下效果显著高于/低于平均水平时，自动识别为潜在变体。例如"对话写作"技能在古风场景效果分 90，在现代场景效果分 70，则识别"古风对话"为潜在变体。 | Draft | P1 |
| SK-22 | 变体创建 | 潜在变体经 LLM 提炼为独立变体技能，关联到基础技能（`parent_skill_id`）。变体继承基础技能的核心规则，针对特定场景进行优化调整。变体版本号独立于基础技能（如"对话写作 v2.0"的"古风对话"变体为 v1.0）。 | Draft | P1 |

## 5. 验收标准（AC）

### AC-SK-01：GEPA 闭环完整流程

**前提条件：** 已创建作品，已完成至少 1 次写作任务，已配置 API Key

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 完成一次写作任务 | 系统自动记录 BehaviorRecord（含 Prompt、角色状态、工具调用、生成内容、使用技能） |
| 2 | 作者对生成内容进行修改（保留 60%，修改 30%，删除 10%） | 采纳率计算为 60% + 30% x 0.5 = 75% |
| 3 | ReviewerAgent 对内容评分 85 分 | 综合效果分 = 75% x 0.4 + 85/100 x 0.6 = 81 |
| 4 | 等待 GEPA 异步执行完成 | 使用的技能效果评估完成，效果分 81 记录到技能统计 |
| 5 | 累计使用同一技能 5 次且效果分均 >80 | 触发正向优化，生成新版本（v1.0 -> v1.1） |
| 6 | 查看技能版本历史 | 显示 v1.0 和 v1.1 两个版本，含变更说明和优化依据 |

### AC-SK-02：技能自动推荐

### 7.3 与 Agent 体系集成说明

GEPA 闭环与 ReviewerAgent 评分流程深度集成，形成完整的质量反馈闭环：

1. **ReviewerAgent 评分触发**：每次写作任务完成后，ReviewerAgent 对生成内容进行多维度评分（0-100），评分结果作为 GEPA 闭环效果评估（E 阶段）的核心输入。
2. **反面技能沉淀**：当 ReviewerAgent 评分 <60（决策 #44）时，GEPA 闭环的 P 阶段自动将该写作模式沉淀为反面技能（Anti-pattern），记录失败原因和正确做法对照。
3. **技能优化反馈**：GEPA 闭环优化后的技能通过 ContextRouter 注入 WriterAgent 上下文，影响后续写作质量，形成"写作 -> 评估 -> 优化 -> 沉淀 -> 改进写作"的闭环。
4. **Orchestrator 协调**：Orchestrator 在调度 WriterAgent 时，自动获取推荐技能列表并注入上下文；写作完成后 Orchestrator 触发 GEPA 闭环异步执行。

### 7.4 外部依赖

| 依赖 | 说明 | 必要性 |
|------|------|--------|
| LLM API | 技能提炼、效果评估分析、策略优化、变体发现、跨作品适配 | P0 |
| PostgreSQL + zhparser | 全文搜索和中文分词 | P0 |
| Supabase PostgreSQL | 技能数据持久化存储 | P0 |
