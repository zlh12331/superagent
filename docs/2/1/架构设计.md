# 网文写作助手 — 架构设计

> 借鉴 Qwen Code 的 Skill/Command/Agent 文件驱动架构
> **核心理念：Python 只负责拼 prompt、调 API、存数据，所有"智能"写在 markdown 文件里**

---

## 一、整体架构

```
用户终端输入
      │
      ▼
┌──────────────────────────────────────────────┐
│  core/engine.py         核心引擎              │
│                                              │
│  ① 解析用户输入 → 匹配 skill/command          │
│  ② 加载对应的 SKILL.md / command.md           │
│  ③ 从 SQLite 读取当前作品的数据上下文           │
│  ④ 拼装完整 prompt = skill指令 + 数据 + 用户输入 │
│  ⑤ 调 DeepSeek API                            │
│  ⑥ 解析返回结果，按 skill 定义的存数据规则写入 DB │
│  ⑦ 展示结果给用户                              │
└──────────────────────────────────────────────┘
      │
      ├── .writing/skills/     ← 技能定义文件（所有"智能"在这里）
      ├── .writing/commands/   ← 快捷命令定义
      ├── .writing/agents/     ← 子 Agent 定义
      ├── core/llm.py          ← DeepSeek API 调用
      ├── core/db.py           ← SQLite CRUD
      └── data/novel_writer.db ← 作品数据
```

**关键决策：引擎不内置任何写作逻辑，一切写作能力来自 .writing/ 目录下的文件。**

## 三、Skill 设计（核心）

### 3.1 SKILL.md 格式

沿用 Qwen Code 的 YAML frontmatter + Markdown 正文：

```markdown
---
name: write-chapter
description: 续写新章节。当用户说"续写""写下一章""接着写"时触发
model: flash            # 使用的模型：flash / pro
stream: true            # 是否流式输出
---

# 章节写作

## 数据需求
从数据库加载以下数据拼入 prompt：
- {{project.name}} — 作品名
- {{latest_chapter}} — 最新一章内容摘要
- {{characters}} — 当前作品的角色列表和状态
- {{foreshadows}} — 活跃伏笔列表
- {{style}} — 风格宪法

## 系统提示
你是一位专业的网文写手...（此处省略具体提示词）

## 用户输入处理
将用户输入的写作指引添加到 prompt 末尾

## 结果处理
- 将生成的正文保存到 chapters 表
- 更新最新章节号
- 显示"✅ 第 X 章已保存"
```

### 3.2 引擎如何加载和执行 Skill

```
① loader.py 扫描 .writing/skills/*/SKILL.md
   读取 frontmatter 构建技能索引
   → [{name: "write-chapter", description: "续写新章节...", model: "flash"}, ...]

② 用户输入 → engine 匹配技能
   用关键词/语义匹配 description 字段
   匹配到 → 加载该 SKILL.md 正文

③ 按 SKILL.md 中"数据需求"从 SQLite 读取数据

④ 拼装 prompt = system提示 + 数据上下文 + 用户输入

⑤ 调 DeepSeek（按 frontmatter 指定的 model/stream 参数）

⑥ 按"结果处理"规则解析并存储
```

### 3.3 Skill 执行流程

```
用户: "续写第三章"
        │
        ▼
引擎匹配 → write-chapter skill
        │
        ▼
加载 SKILL.md → 读取"数据需求"段
        │
        ▼
从 DB 读: 作品名、角色列表、大纲、最新章节内容、伏笔、风格
        │
        ▼
拼 prompt = [系统提示] + [角色数据] + [大纲] + [最新章节] + [伏笔] + "请续写第三章"
        │
        ▼
调 DeepSeek (flash, stream=true)
        │
        ▼
流式输出到终端
        │
        ▼
保存到 SQLite chapters 表
        │
        ▼
显示 "✅ 第三章已保存 (2863字)"
```

## 四、Command 设计

### 4.1 Command 格式

```markdown
---
description: 管理角色设定。创建、查看、编辑角色
type: data               # data=数据操作 / query=查询 / config=配置
---

# 角色管理

引擎执行逻辑（非 LLM，直接操作 DB）：
1. 列出当前作品所有角色
2. 用户选择操作：查看/添加/编辑/删除/关系管理
3. 执行对应 DB 操作
```

### 4.2 Command 与 Skill 的区别

| | Skill | Command |
|--|-------|---------|
| 触发方式 | 自然语言匹配 | 斜杠命令 `/character` |
| 是否调 LLM | 是（核心就是调 DeepSeek） | 否（直接操作数据库） |
| 用途 | 写作、审查、大纲生成等创作类 | 角色/设定/伏笔等数据管理类 |
| 复杂度 | 多步骤工作流 | 单步操作 |

## 五、Agent 设计

### 5.1 Agent 格式

```markdown
---
name: reviewer
description: 章节审查助手，检查设定/逻辑/风格一致性
model: pro              # 审查用 pro + 思考模式
thinking: true
---

# 审查 Agent

你的任务是审查网文章节的一致性...

## 可用工具
- read_chapter(chapter_id) — 读取章节内容
- list_characters(project_id) — 列出角色
- list_world_settings(project_id) — 列出设定
- get_style_constitution(project_id) — 获取风格宪法

## 输出格式
必须输出 JSON：
{
  "overall_score": 0-100,
  "issues": [...],
  "summary": "..."
}
```

### 5.2 Agent 与 Skill 的关系

- **Skill** 是"引擎主动执行的工作流"——引擎读到 SKILL.md，按步骤执行
- **Agent** 是"派给 DeepSeek 独立完成的任务"——把整套 prompt + 工具权限给 DeepSeek，让它自主完成
- 简单说：Skill 是引擎主导，Agent 是 DeepSeek 主导

## 六、引擎核心循环

```
启动
  │
  ▼
loader 扫描 .writing/ 目录 → 构建 skills/commands/agents 索引
  │
  ▼
用户选择/创建作品 → 进入交互循环
  │
  ▼
┌─────────────────────────────────────────┐
│ 交互循环：                                │
│                                         │
│  while True:                             │
│      user_input = input("> ")           │
│                                         │
│      if user_input 是斜杠命令:            │
│          加载对应 command → 执行 DB 操作   │
│                                         │
│      else:                              │
│          匹配 skill（按 description 关键词）│
│          加载 SKILL.md                   │
│          从 DB 读数据                    │
│          拼 prompt → 调 DeepSeek         │
│          存结果 → 展示                   │
│                                         │
│      if user_input 触发复杂子任务:         │
│          加载 agent → 派给 DeepSeek 独立执行│
└─────────────────────────────────────────┘
```

## 七、与旧设计的对比

| 维度 | ❌ 旧设计（菜单式） | ✅ 新设计（文件驱动） |
|------|-------------------|-------------------|
| 智能在哪 | Python 代码里写死的 | **`.writing/skills/*/SKILL.md` 文件里** |
| 扩展功能 | 改 Python 代码、加菜单项 | 新建一个 SKILL.md 文件即可 |
| 用户交互 | 层层菜单 (1→2→3) | 自然语言输入 + 斜杠命令 |
| 引擎职责 | 写死的业务逻辑 | 通用加载-拼prompt-调API-存结果 |
| 灵活性 | 菜单固定，难以调整 | 修改/新增 SKILL.md 即可改变行为 |
| prompt 管理 | 散落在 Python 函数里 | 集中管理在 markdown 文件中 |

## 八、实现策略

### Phase 1：核心引擎 + 基本 skill
1. `core/db.py` — SQLite 数据管理（不变，已写好）
2. `core/llm.py` — DeepSeek API 封装（不变，已写好）
3. `core/loader.py` — 扫描 .writing/ 目录，解析 YAML frontmatter
4. `core/engine.py` — 主循环：匹配 → 加载 → 拼 prompt → 调 API → 存结果
5. `.writing/skills/write-chapter/SKILL.md` — 第一个 skill
6. `.writing/skills/review-chapter/SKILL.md` — 审查 skill
7. `.writing/commands/` — 基本数据管理命令

### Phase 2：更多 skill + agent
1. `.writing/skills/generate-outline/`
2. `.writing/skills/rewrite/`
3. `.writing/skills/get-inspiration/`
4. `.writing/agents/reviewer.md`

### 核心原则（定下来就不改）
- **引擎不写任何特定写作逻辑**，所有技能写在 SKILL.md 里
- **SKILL.md 是 prompt 模板 + 执行步骤**，不是 Python 代码
- **Command 是数据操作**，不调 LLM
- **Agent 是独立子任务**，DeepSeek 自主完成
