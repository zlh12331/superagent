# 28 · 托盘与关窗语义规格（后台驻留）

- **状态**：设计定稿（拍板项见 §10），待实施
- **范围**：主进程托盘（`src/main/tray.ts`）、窗口关窗语义（`src/main/window.ts` + `index.ts` 退出链）、
  设置契约（`settings.window` 域）、开机自启
- **不含**：托盘内嵌聊天窗 / 托盘内直接审批（第二主界面形态，明确不做，见 §13）

## 1. 定位与原则

托盘的定位从「唤回入口」升级为「**后台驻留中心**」。

动机（产品事实）：本应用有三类**天然需要后台常驻**的能力——Agent 长任务（终端 /
workflow 可能运行很久）、IM 渠道接入（7 个适配器长连接驻留主进程）、**定时任务**
（cronService 在主进程触发 Agent 回合）。而现状是 `window-all-closed` 在
Windows/Linux 直接 `app.quit()`——窗口一关，进程退出，以上全部停止。
「定时任务」的用户预期（关掉应用也能到点触发）与「关窗即死」的实现是冲突的。

原则：

1. **关窗 ≠ 退出**（默认）：点 X 最小化到托盘，进程与全部后台能力继续；退出走
   托盘菜单 / 设置中的显式动作。
2. **最小化不打扰**：最小化到托盘不中断回合，因此关窗时不弹任何确认框
   （「运行中回合」协商只属于**退出**路径）。
3. **退出语义不变**：托盘退出与任何退出路径都走完整善后链（协商 → 异步清理 → exit），
   与点 X 历史行为一致的部分保持一致。
4. **托盘有状态**：图标反映回合运行 / 更新就绪，让"应用还在后台干活"可感知。
5. **文案跟随语言**：托盘菜单不再硬编码中文。

## 2. 基线事实（现状）

| 项 | 现状 |
|---|---|
| 托盘 | `src/main/tray.ts`（87 行）：幂等创建；图标为应用图标缩 16×16（空图回退默认）；tooltip = 应用名；左键 `showMainWindow()`（restore+show+focus）；右键菜单两项（显示 / 退出），**文案硬编码中文** |
| 关窗语义 | **只有一种**：点 X → 关窗协商（有回合确认）→ 窗口关闭 → `window-all-closed` → 非 darwin `app.quit()` |
| 后台能力 | IM 渠道适配器与 cronService 均驻留主进程——关窗即全停 |
| 托盘状态 | 图标静态，无回合运行 / 更新就绪表达 |
| 配套 | 无开机自启（未调 `setLoginItemSettings`）；设置中无窗口/托盘行为项 |
| 通知 | 回合通知独立于托盘（`notification.ts`），点击仅 `win.show()`，不导航到会话；**payload 未携带 sessionId**（"导航到会话"需先扩展通知，见 §8） |
| 单实例 | `app.requestSingleInstanceLock` 已存在（`index.ts` 主实例 / 第二实例聚焦已有窗口）——托盘常驻的"二次启动"语义已具备，无需新增 |

## 3. 关窗语义（核心决策）

### 3.1 行为矩阵

| 场景 | `closeAction = minimize`（默认） | `closeAction = quit` |
|---|---|---|
| 点 X（无回合在跑） | 窗口隐藏（`win.hide()`），进程驻留托盘 | 直接关窗 → 退出 |
| 点 X（有回合在跑） | 窗口隐藏，**不弹确认**（回合继续） | 关窗协商确认（现行行为） |
| 托盘菜单「退出」 | 退出协商（有回合确认）→ 完整善后 → 退出 | 同左 |
| `app.quit()` / 退出链 | 照常（before-quit 协商与善后不受影响） | 同左 |

要点：**最小化路径完全不经过「运行中回合」协商**——最小化不中断回合，无需确认；
确认只属于**退出**路径（托盘退出 / quit 模式下的点 X）。

### 3.2 实现要点

- `window.ts` 的 `close` 处理器在**关闭事件发生时实时读取** `settings.window`
  （同步 `readSetting`，单行 SQLite 读，开销可忽略）——用户改设置后立即生效，
  无缓存失效问题；缺失/损坏一律按默认 `minimize` 处理。
- 真实退出路径的放行条件（现有 `isQuitting` / `isCloseConfirmed` /
  `CODE_AGENT_SKIP_CLOSE_GUARD`）优先于关窗行为判定——退出链中的 close 事件
  不应被"最小化"劫持。`isQuitting` 标志随关闭协商标志一并迁入 `quit-state.ts`。
- `minimize` 的实现是 `win.hide()`（从任务栏消失，仅托盘可达），不是
  `win.minimize()`（那只是缩到任务栏，不构成"托盘驻留"）。
- **隐藏后的资源语义**：渲染层被 Chromium 后台节流自动降频（timer/动画），无需
  额外处理——这是 `hide()` 方案的附带优点；而主进程侧（Agent 回合 / IM 长连接 /
  cron）不经过 Chromium 调度，**不受节流影响**，后台能力完整。
- **darwin 不参与**：macOS 原生惯例即"关窗不退出"（Cmd+Q 才退出），不读
  `closeAction`，保持平台行为。

### 3.3 首次最小化的引导

默认行为从「退出」变为「最小化」，存在可发现性问题（用户点 X 后找不到应用）。
采用**非模态一次性引导**：首次隐藏时发一条系统通知——「已最小化到托盘，点击唤回；
退出请用托盘菜单」，点击通知即唤回窗口。已提示标记存 `app_settings`
（主进程直写，渲染层不感知）。不做模态弹窗（不打断用户，成本更低）。

## 4. 设置契约

- `SETTING_KEYS` 增加 `'window'`；渲染层 settings-store 新增 `WindowSettings`
  分组（照 `experimental` 分组写法，写穿透落库）。
- 契约：`WindowSettings { closeAction: 'quit' | 'minimize' }`，默认 `'minimize'`。
- 主进程在关窗事件中实时 `readSetting('window')`——不缓存、不依赖渲染层推送。
- 设置界面：设置 → 通用，`SegControl` 两态（「最小化到托盘」/「退出应用」）+ 一句
  说明文案。

## 5. 托盘状态表达

| 状态 | 图标 | 来源 |
|---|---|---|
| 空闲 | 默认图标 | — |
| 回合运行中 | 角标（强调色圆点） | Agent 回合开始 / 结束（主进程内部事件） |
| 更新就绪 | 角标（另一色） | `update-downloaded`（更新系统 §27 直接接入） |
| 更新下载中 | 角标（进度色） | 下载进度事件 |

tooltip 同步携带状态文本（如「运行中 · 修复登录页」/「有可用更新 v1.2.1」）。

**状态优先级**（多状态并存时取最高）：运行中 > 更新下载中 > 更新就绪 > 空闲。

**状态事件源**：回合生命周期复用主进程既有的 `onTurnEvent` 总线（`hook-registry.ts`
已指明其存在，不重复实现、不轮询 `hasRunningAgentTurns`）；更新状态复用本服务
（§27）的下载进度 / 就绪事件。托盘模块内一个状态机消费这两路输入，统一重建
图标与菜单。

## 6. 动态菜单

右键菜单从静态两项升级为状态驱动 + 快捷操作（每次状态变化重建，`setContextMenu`
成本低）：

```text
● 正在运行 · 修复登录页           ← 状态行（只读）
──────────────
新建会话
最近会话 ▸
──────────────
检查更新 / 重启并安装 v1.2.1      ← 就绪时变为安装动作
开机自启                    ☑
关闭时最小化到托盘          ☑
──────────────
退出
```

- 「重启并安装」复用已落地的两段式安装链路（quit-for-update → 退出链末端拉起）。
- 「退出」保持走完整善后链（不变）。
- 菜单文案不再硬编码：托盘模块内置 `zh-CN` / `en` 双语文案表，构建菜单时按
  `settings.language` 取用；语言变更时重建菜单。

### 6.1 菜单动作的落地口径

- 「新建会话」：主进程直接调 SessionService 创建，随后广播深度链接
  （`code-agent://session/<id>`）唤回并导航——复用既有机制，不新造导航通道。
- 「最近会话 ▸」：数据源复用 `session:listRecentDirs`，点击导航同上。
- 「重启并安装」：复用已落地的两段式安装链路（quit-for-update → 退出链末端拉起）。

## 7. 开机自启

- `app.setLoginItemSettings({ openAtLogin, args: ['--hidden'] })`：开机自启时以
  `--hidden` 启动（不弹窗口，仅托盘驻留）——没有它，"最小化到托盘"在重启后失效。
- 托盘菜单提供开关（读取 `app.getLoginItemSettings()` 回显，OS 持久化，不需要
  额外设置字段）。
- **`--hidden` 的消费点（实现必需，此前遗漏）**：`index.ts` 启动期检查
  `process.argv` 含 `--hidden` → 窗口创建后立即 `hide()`（窗口仍要创建——托盘与
  事件订阅依赖它），且优先于 window-state 的"恢复上次显示状态"。
- **macOS dev 限制**：未打包环境下 `setLoginItemSettings` 不可靠（Electron 平台
  差异），该开关仅在打包版承诺生效（设置界面注明）。

## 8. 通知与联动

- 回合完成通知点击：从「仅显示窗口」升级为「唤回 + 导航到对应会话」（复用深度链接
  机制或 ui-store 导航）。
- 更新就绪通知 / 首次最小化引导通知：点击唤回窗口。
- **前置改造**：当前通知 payload 未携带 sessionId——「导航到对应会话」需先扩展
  `notification.ts` 的通知入参（回合结束时携带 sessionId），否则只有唤回、没有
  导航目的地。

## 9. 平台细节

- **macOS template 图标**（已记录的待办）：`trayTemplate.png` + `trayTemplate@2x.png`，
  系统自动深浅色适配；其余平台用多尺寸图标（16/24/32）。
- **Linux**：部分桌面环境（AppIndicator）左键行为受限，右键菜单必须始终可用（兜底）。
- **DPI**：Windows 下按缩放比选择尺寸，避免模糊。
- **无托盘环境降级（边界，必须处理）**：Linux 部分桌面环境（GNOME 默认配置）不
  显示 AppIndicator——此时 `closeAction = minimize` 会让窗口藏起来找不回，且
  Electron 无法可靠探测托盘是否可见。降级策略：Linux 上 `closeAction` 默认强制
  为 quit（与 darwin 同类的平台化默认），设置界面允许显式改 minimize 但文案注明
  "需桌面环境支持托盘图标"；全局快捷键唤回列 P2。

## 10. 已拍板项

| 项 | 结论 | 说明 |
|---|---|---|
| 关窗默认行为 | **minimize**（用户拍板，2026-09-19） | 「关窗后 Agent 继续干活」是产品定位；关窗协商确认保留于退出路径 |
| 首次最小化引导 | 一次性系统通知（非模态） | 不打断用户；点击即唤回 |
| darwin | 不读 `closeAction` | 保持 macOS 原生"关窗不退出"语义 |
| 退出确认 | 保留 | 最小化不打扰回合；退出（中断回合）必须确认，两段确认语义不同 |
| 设置项形态 | 单 SegControl 两态 | 不做三态（无第三种关窗行为） |

## 11. 落地分期

**P0（核心语义）**

1. `settings.window.closeAction`（默认 minimize）：`SETTING_KEYS` + settings-store
   分组 + 通用分区 SegControl。
2. `window.ts` 关窗处理器：实时读设置 → minimize 则 `hide()`（跳过回合协商）；
   quit 走现行协商。`isQuitting` 标志迁入 `quit-state.ts` 并对关窗处理器可见。
   Linux 上未显式设置时平台化回退为 quit（§9 无托盘降级）。
3. 首次最小化系统通知（一次性标记存 `app_settings`）。
4. 托盘菜单 i18n（双语文案表 + `settings.language` 驱动 + 语言变更重建）。

**P1**：回合运行中 / 更新就绪图标态与 tooltip、动态菜单（状态行 + 新建会话 + 更新
入口 + 开机自启开关）、通知点击导航会话。

**P2**：macOS template 图标与多尺寸资源、Linux AppIndicator 细节、下载中角标。

## 12. 验收

- **单测**：关窗行为矩阵（minimize 隐藏不协商 / quit 协商 / isQuitting 放行）、
  设置缺失与损坏回退默认 minimize。
- **组件测试**：通用分区 SegControl 两态渲染与写穿透。
- **门禁**：typecheck / lint / check:static（i18n 双语、tokens）/ test / knip 全绿。
- **真机**：minimize 下点 X → 托盘驻留、回合继续、cron 到点触发；托盘退出 → 协商 →
  退出；macOS 行为不变。

## 13. 明确不做

- 托盘内嵌聊天窗 / 托盘内直接审批工具调用（第二主界面形态）
- 三态以上关窗行为（无第三种关窗语义）
- 托盘闪烁提醒（用角标与通知表达，闪烁是干扰）
- 自动重启安装（更新就绪且用户无操作时静默重启）——对 Agent 应用有任务中断风险，
  安装始终由用户显式触发
